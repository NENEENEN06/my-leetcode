# 3736. Minimum Moves to Equal Array Elements III

- Difficulty: Easy
- Topics: Array, Math
- Language: C++
- 题目链接: https://leetcode.cn/problems/minimum-moves-to-equal-array-elements-iii/

## 题目

给定整数数组 `nums`，每次操作可以把任意一个元素加 1。求让所有元素相等所需的最少操作次数。

## 我的思路

- 核心思想：**最终高度只能是数组最大值**。操作只会让元素变大，任何一个元素都不能降到别人那里，所以「拉平到的目标值」不可能低于 $m = \max(nums)$；取 $m$ 即可一次到位。于是答案就是 $\sum_{i} (m - nums_i)$。
- 但代码没有先求最大值再求和，而是**一趟扫描就地拉平前缀**：把 `nums[i]` 当作「`nums[0..i]` 已经拉平后的公共高度」，边走边累计代价。
- 算法流程（`i` 从 1 开始）：
  1. 若 `nums[i] < nums[i-1]`：前 $i$ 个元素的公共高度是 `nums[i-1]`，当前元素比它矮，补上差值 `nums[i-1] - nums[i]`，代价就是这个差值；再把 `nums[i]` 写成 `nums[i-1]`，保持「前缀已拉平」的不变式。
  2. 否则 `nums[i] >= nums[i-1]`：公共高度被抬到 `nums[i]`，抬升量 $d = \texttt{nums[i]} - \texttt{nums[i-1]}$，左边 $i$ 个元素每个都要补 $d$，代价 $i \times d$；`nums[i]` 不用改。
- 为什么能得到正确答案：循环结束后 `nums[n-1]` 就是整个数组的最大值，而每一步累加的正是「把当前元素纳入已拉平前缀」的真实增量，所有增量之和等于 $\sum (m - nums_i)$，与最优解一致。
- 关键状态 / 变量：`nums[i-1]`（前缀公共高度，就地复用原数组）、`i`（左边有多少个元素要一起抬）、`res`（累计代价）。

## 代码

```cpp
// 3736. Minimum Moves to Equal Array Elements III
// 每次只能给一个元素 +1，最优目标值必然是数组最大值；一趟扫描时
// 维护 nums[0..i] 已经拉平后的公共高度（就地写回 nums[i]），
// 高度抬升 d 时左边 i 个元素要各补 d，抬不动就直接把当前元素补上去。
class Solution {
public:
    int minMoves(vector<int>& nums) {
        int res = 0;                      // 累计操作次数
        int n = nums.size();

        for (int i = 1; i < n; i++) {
            if (nums[i] < nums[i - 1]) {
                // 当前元素比左侧已拉平的高度低：把它补上去，代价就是差值
                res += nums[i - 1] - nums[i];
                nums[i] = nums[i - 1];
            }
            else {
                // 当前元素更高：前面的 i 个元素都要各补 (nums[i] - nums[i-1])
                res += i * (nums[i] - nums[i - 1]);
            }
        }

        return res;
    }
};
```

## 代码分析

- 正确性：正确。本机对拍 $2\times10^5$ 组随机输入（$n\le8$，值域 $[1,6]$，含大量重复值），与闭式解 $\max\cdot n-\sum$ 逐组比对零差异；题面两个样例 $[2,1,3]\to3$、$[4,4,5]\to2$ 也吻合。
- 关键实现：一趟循环同时完成「求最大值」和「累加差距」，把最优目标值的求解和代价统计合并成一次扫描，不用二分、不用先求 max。
- 潜在 Bug：无越界与溢出风险——$n\le100$、$nums_i\le100$ 时 `res` 上界是 $99\times100=9900$，`i * (nums[i] - nums[i-1])` 最大 $99\times99$，都在 `int` 范围内。
- 可以改进的地方：
  - 入参 `nums` 被就地改写（变成了「前缀拉平」后的数组）。本题调用方不关心入参，但若拿去做复用调用，第二遍跑就会得到 0；想保留原数组就换成局部变量 `int curMax = nums[0];` 缓存高度，代价是多一个变量。
  - 若追求「一行流」可写成 `return accumulate(...)` 形式，但可读性不如现在这种保持不变式的写法。

## 复杂度

- 时间复杂度：$O(n)$，一次遍历，每个下标只做常数次运算。
- 空间复杂度：$O(1)$，只用了 `res`/`n`/`i` 三个标量（就地改写 `nums`，没有额外数组）。

## 易错点

- **目标值选错**：因为操作只会加不会减，目标只能是最大值；把它当成「平均值」去凑就要额外做向上取整，还容易写成浮点。
- **两个分支的系数搞混**：`nums[i]` 更矮时只补 `1` 份差值；更高时前面的 `i` 个元素都要补，系数是 `i` 不是 `i+1`（下标从 0 起，当前元素本身不用补）。
- **数组已有重复值**：`nums[i] == nums[i-1]` 走 else 分支，差值为 0，代价为 0，不会错；不用单独判等。
- **`int` 溢出**：本题值域小没问题，换成 $10^9$ 量级就要用 `long long` 存 `res`。

## 总结

「每次只能把单个元素加 1」这类拉平题，先想清楚目标值（只能是最大值），答案就是 $\sum (m - a_i)$；求这个和不必先扫一遍找 max——**把前缀拉平的不变式带在身上**，边走边算增量即可，一趟搞定。

## 复盘

- 关键突破点：想到「`nums[i-1]` 本身就是前缀公共高度」，于是不用维护额外的最大值变量，也不用来回扫两遍。
- 下次看到「只能单点 +1 / -1，求拉平最小代价」的题，先定目标值，再看能不能用前缀不变式合并成一次扫描。
