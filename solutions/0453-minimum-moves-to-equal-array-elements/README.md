# 453. Minimum Moves to Equal Array Elements

- Difficulty: Medium
- Topics: Array, Math
- Language: C++
- 题目链接: https://leetcode.cn/problems/minimum-moves-to-equal-array-elements/

## 题目

给定一个长度为 $n$ 的整数数组，每次操作可以把其中 $n-1$ 个元素各自加 $1$。求最少多少次操作能让所有元素相等。

## 我的思路

- 核心思想：**「$n-1$ 个元素同时加 1」等价于「只让剩下的那 1 个元素减 1」**。这两个操作对元素之间「谁比谁大多少」的影响完全相同，而后者只动一个数，好算得多。
- 既然每次只能把一个元素往下降 1，那最优策略就是：把所有元素都削到数组最小值 $m$。比 $m$ 高多少就要削多少刀，累计就是答案。
- 使用的数据结构：只需要一次遍历同时维护「总和」和「最小值」，不需要额外空间。
- 算法流程：
  1. 遍历数组，累加得到 $\text{sum}$，同时求出 $\min$；
  2. 返回 $\text{sum} - n \times \min$。
- 为什么能够得到正确答案：设最终所有元素都等于 $t$。由于操作只能让元素「相对变大」而不改变它们之间的差，因此 $t$ 不可能小于原最小值 $m$——否则就要把最小值往上抬，而抬它必然同时抬动别人，等价于只降低剩下的那个，绕回同一个问题。目标态取 $t=m$ 时，每个元素 $a_i$ 需要的下降量是 $a_i - m$，总和 $\sum(a_i - m)=\text{sum}-n\cdot m$，这就是下界；而这个下界显然可达（每次挑一个大于 $m$ 的元素减 1，直到全部等于 $m$），所以它也是最优解。
- 关键状态 / 变量：`sum`（总和，必须用 `long long`）、`minNum`（当前最小值）。

## 代码

```cpp
// 453. Minimum Moves to Equal Array Elements
// 每次给 n-1 个元素 +1，等价于每次只挑一个元素 -1；把所有元素削到最小值即可，
// 答案 = 总和 - n * 最小值。
class Solution {
public:
    int minMoves(vector<int>& nums) {
        // 注意：n ≤ 1e5、|nums[i]| ≤ 1e9，总和最大 1e14，int 装不下，这里必须用 long long
        long long sum = nums[0];
        int minNum = nums[0];
        int n = nums.size();

        for (int i = 1; i < n; i++) {
            sum += nums[i];
            minNum = min(minNum, nums[i]);
        }

        return static_cast<int>(sum - static_cast<long long>(minNum) * n);
    }
};
```

## 代码分析

- 正确性：正确。返回 $\text{sum}-n\cdot m$，与「把所有元素削到最小值所需刀数」一致。样例 $[1,2,3]$ 得 $6-3\times1=3$，$[1,1,1]$ 得 $3-3=0$，均符合。
- 关键实现：一次遍历同时更新 `sum` 与 `minNum`，$O(n)$ 时间、$O(1)$ 额外空间。
- 潜在 Bug：**`sum` 必须用 `long long`**。题面只保证「答案」能放进 32 位整数，没有保证中间量——$n\le10^5$、$|a_i|\le10^9$ 时总和可达 $10^{14}$，远超 `int` 的 $2.1\times10^9$。原版用 `int sum` 时，`sum` 与 `minNum * n` 会同时溢出同样的倍数而恰好互相抵消，本地实测仍能得到正确结果（例如 $[10^9\times9,\ 999999900]$ 返回 900），但这是**未定义行为**：`g++ -fsanitize=undefined` 会在加法和乘法两处报 `signed integer overflow`，换编译器或更激进的优化就未必幸运。
- 可以改进的地方：无。已经是最优的时间与空间。

## 复杂度

- 时间复杂度：$O(n)$，一次遍历。
- 空间复杂度：$O(1)$，只用了几个标量。

## 易错点

- **溢出**：这是本题唯一的坑，`sum` 与 `minNum * n` 都要用 64 位。
- **把操作理解反**：容易纠结「每次要同时抬 $n-1$ 个」，实际上反过来看「只降 1 个」就一目了然；这层等价转换是解题的关键。
- 若数组已全部相等，答案应为 $0$，公式自然给出 $n\cdot m - n\cdot m=0$。

## 总结

「对 $n-1$ 个元素做统一操作」这类题，第一步永远先做一次「补集转换」：把它换成「对 1 个元素做反向操作」。转换之后，原本要同时维护多个元素的进程就退化成逐个削峰，答案直接是「总和 − $n$ × 最小值」。
