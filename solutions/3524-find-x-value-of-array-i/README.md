# 3524. Find X Value of Array I
- Difficulty: Medium
- Topics: Array, Dynamic Programming, Math
- Language: C++
- 题目链接: https://leetcode.cn/problems/find-x-value-of-array-i/

## 题目
给定数组 `nums` 和整数 `k`，返回长度为 `k` 的数组 `result`，其中 `result[x]` 表示「元素乘积除以 k 的余数恰好为 x」的**子数组个数**（子数组是连续的非空片段）。

## 我的思路
朴素做法要枚举 O(n²) 个子数组并当场求积，太慢。关键观察是：**子数组的乘积模 k 只取决于「结束位置」和这个余数**，于是按右端点做 DP，把「以 i 结尾的所有子数组」按乘积模 k 的余数归类计数；又因为转移只用得到上一层，所以用**两个长度为 k 的滚动数组**代替 O(n·k) 的二维表。

- 用 `result[i%2]` 表示「以 i 结尾」的当前层，`result[(i-1)%2]` 是上一层；两者轮流复用，空间从 n·k 降到 2k。
- `ans[r]`：所有子数组里乘积模 k 等于 `r` 的总数（每轮把当前层整行累加进去）。
- 起始：`result[0][nums[0] % k] = 1`，同时计入 `ans`（`n = 1` 时循环不执行，靠这两行给出答案）。
- 转移（i ≥ 1）：先 `nums[i] %= k`，再对上一层的每个余数 `j` 做「延伸一格」的映射：
  `result[i%2][(j*nums[i])%k] += result[(i-1)%2][j]`，**紧接着把刚读过的 `result[(i-1)%2][j]` 清零**。
- 最后补上「只含 `nums[i]` 的子数组」：`result[i%2][nums[i]]++`，并把当前层整行加进 `ans`。

清零这一步是滚动数组的关键：i 这一轮写的是 `i%2`，两轮后它又会变回「当前层」，如果不在用过之后清空，两轮前的旧值会被重新累加进去，答案偏大。

为什么正确：以 i 结尾的子数组只有两种来源——长度 1 的 `[i]`，或「以 i-1 结尾的某个子数组再接上 `nums[i]`」；二者互不重叠且覆盖全部。乘法取模满足 `(a×b) mod k = ((a mod k)(b mod k)) mod k`，所以只需保留余数，不必保存真实乘积（真实乘积必然溢出）。

特别地，一旦某个 `nums[i] % k == 0`，`j × 0 = 0`，所有延伸到它的子数组余数都落到 0，符合「乘积含因子 k 则余数为 0」。

## 代码
```cpp
class Solution {
public:
    vector<long long> resultArray(vector<int>& nums, int k) {
        int n=nums.size();
        vector<vector<long long>>result(2,vector<long long>(k,0));
        vector<long long>ans(k,0);
        result[0][nums[0]%k]++;
        ans[nums[0]%k]++;
        for(int i=1;i<n;i++){
            nums[i]%=k;
            for(int j=0;j<k;j++){
                result[i%2][(j*nums[i])%k]+=result[(i-1)%2][j];
                result[(i-1)%2][j]=0;
            }
            result[i%2][nums[i]]++;
            for(int j=0;j<k;j++){
                ans[j]+=result[i%2][j];
            }
        }
        return ans;
    }
};
```

## 代码分析
- 正确性：正确。随机对拍 40000 组（n ≤ 12、k ∈ [1,7]，含 10⁹ 量级大数、含 0 元素）与 O(n²) 暴力枚举零不一致；n=3000 随机 20 组与先前的 O(n·k) 二维版结果完全一致；**同一输入连续调用两次结果相同** —— 这一条专门用来验证「用过即清」是否落实（残留状态会在第二次调用暴露）。
- 关键实现：
  1. 读写顺序正确：先 `+=` 读上一层，再清零，顺序颠倒就会把数据抹掉；
  2. `nums[i]` 只取模一次并在本轮反复使用，避免重复计算；
  3. 「只含自己的子数组」放在通用转移之后也成立，因为两步都是对同一格做加法，加法可交换。
- 潜在 Bug：无。
- 可以改进的地方：`nums[i] %= k` 仍然就地改写了入参数组（纯副作用），建议改成 `int m = nums[i] % k;` 只读入参；如果想省掉「清零上一行」这件事，也可以在每轮开头把当前层整体清零（`fill`），代价是多一趟 O(k) 写。

## 复杂度
- 时间复杂度：O(n·k)。每个位置两次长度为 k 的循环（映射转移 + 累加），k ≤ 5 时等价于 O(n)。
- 空间复杂度：**O(k)**。两个长度为 k 的滚动数组 + 长度 k 的答案数组；相比二维版 O(n·k)（n=10⁵、k=5 时约 4 MB）降到几十字节。

## 易错点
- **忘记清零上一层**：滚动数组最经典的坑。旧值残留会在一轮之后被重新加进来，计数偏大；而且「单次调用」可能碰巧看不出问题，连调两次或换组数据才暴露。
- **清零位置写错**：必须「先读后清」，写成先清再读就把待转移的数据丢掉，答案偏小。
- **下标复用写错**：`i%2` 与 `(i-1)%2` 必须成对使用；若两处都写成固定下标，滚动就退化成覆盖。
- **n=1 未单独处理**：循环体从 i=1 开始，`n=1` 时完全靠 `result[0][…]` 与 `ans[…]` 两行给出结果。
- **用 `int` 存计数**：子数组总数最大约 5×10⁹（n=10⁵），`int` 会溢出，必须 `long long`。实测 n=10⁵ 全 1、k=5 时答案正是 5 000 050 000。
- **k=1 的边界**：任何数对 1 取模都是 0，答案是 n(n+1)/2，可当自检用例。
- **想直接算乘积再取模**：真实乘积有 n 个因子，必然溢出；必须每一步取模。

## 总结
「统计所有子数组的某个聚合量的余数分布」通用套路是**按右端点 DP + 用余数压缩状态**：新元素到来时，把上一层每个余数映射成新余数（乘法是 `(j × a) % k`）后再累加，并把整层汇入全局答案。由于乘法对取模可交换，状态空间只要 k 个；又因为只依赖上一层，**两个滚动数组**即可把空间压到 O(k)。写滚动版时，「用过的那一层立刻清零」是正确性的一部分，不是可选优化。

## 复盘
- 容易想错的地方：第一反应是枚举子数组并维护乘积（n=10⁵ 必然超时）；也可能想用前缀乘积 + 除法，但遇到 0 因子就崩。
- 关键突破点：看出「以 i 结尾的子数组」只有「新开一个」和「上一层延伸」两种来源，于是把 O(n²) 枚举降成 O(n·k) 递推；再注意到只依赖上一层，进一步把空间降到 O(k)。
- 下次看到什么特征应该想到这个算法：统计**子数组**个数、聚合操作是乘法/加法且**带取模**、模数很小（这里 k ≤ 5）——直接想「按右端点 DP + 余数状态」，然后再问一句「能不能只留上一层」。
