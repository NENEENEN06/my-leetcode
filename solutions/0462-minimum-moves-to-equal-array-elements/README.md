# 462. Minimum Moves to Equal Array Elements II

- Difficulty: Medium
- Topics: Array, Math, Sorting
- Language: C++
- 题目链接: https://leetcode.cn/problems/minimum-moves-to-equal-array-elements-ii/

## 题目

给定长度 $n$ 的整数数组，每次操作可以把**任意一个**元素加 1 或减 1。求最少多少次操作能让所有元素相等。

## 我的思路

- 核心思想：所有元素最终要收敛到某个值 $t$，总代价是 $\sum |a_i - t|$。这是个经典的中位数问题——**使绝对偏差和最小的点就是中位数**。
- 既然是中位数，就不必真的算出它。排序后数组关于中点对称，把最小的和最大的配成一对：$a_{(n-1)} - a_{(0)}$、$a_{(n-2)} - a_{(1)}$……每一对的差正好等于这两个元素各自走到中位数所花的步数之和。
- 算法流程：
  1. 先 `sort` 排序；
  2. 循环 $i$ 从 $0$ 到 $\lfloor n/2 \rfloor - 1$，累加 `nums[n-1-i] - nums[i]`；
  3. 返回累加结果。
- 为什么能得到正确答案：设目标值为 $t$，代价 $f(t)=\sum|a_i-t|$ 是凸函数，在 $t$ 取中位数时最小。$n$ 为奇数时中位数唯一（正中间那个）；$n$ 为偶数时**区间 $[a_{n/2-1},\,a_{n/2}]$ 内任意值都是最优解**，代价相同。而上面那对「最远两端相减」的写法恰好避开了「偶数个时取哪个」的选择：$a_{n-1-i}-a_i$ 就是这一对元素到区间内任意点的距离之和，与选哪个无关。
- 关键变量：`n`（数组长度）、`res`（累计步数，即答案）。

## 代码

```cpp
// 462. Minimum Moves to Equal Array Elements II
// 让所有元素相等的目标值取中位数时总移动次数最小；排序后让最小与最大配对相减，
// 每一对的差恰好是两端到中位数的距离之和。
class Solution {
public:
    int minMoves2(vector<int>& nums) {
        int n = nums.size();
        int res = 0;

        // 中位数是「绝对偏差之和」最小的点，排序后才能成对取差
        sort(nums.begin(), nums.end());

        for (int i = 0; i < n / 2; i++) {
            res += nums[n - 1 - i] - nums[i];
        }

        return res;
    }
};
```

## 代码分析

- 正确性：正确。排序后成对相减并求和，等价于 $\min_t\sum|a_i-t|$，即所有元素都搬到中位数的总距离。样例 $[1,2,3]$ 得 $(3-1)=2$，$[1,2,9,10]$ 得 $(10-1)+(9-2)=16$，均符合。
- 关键实现：排序 $O(n\log n)$，之后只遍历一半，整体 $O(n\log n)$ 时间、$O(\log n)$ 栈空间（`sort` 的递归）。
- 潜在 Bug：**没有溢出问题**，但值得说明——单次 `nums[n-1-i] - nums[i]` 最大为 $2\times10^9$，仍在 `int` 范围内（$|a_i|\le10^9$）；`res` 是这些非负项的部分和，不会超过最终答案，而题面保证答案适配 32 位，所以 `int res` 是安全的。若数据范围改成 $|a_i|\le10^{18}$，这个 `res` 就得换 `long long`。
- 可以改进的地方：无。这个写法已经是最优的常数级实现。

## 复杂度

- 时间复杂度：$O(n\log n)$，瓶颈在排序。
- 空间复杂度：$O(\log n)$，`sort` 的内部栈；不计排序则为 $O(1)$。

## 易错点

- **别去找「平均值」**：让所有元素相等用平均值最小化的是平方和，本题是绝对值和，要的是中位数。这是 462 与 453 之外最容易混淆的一点（453 每次动 $n-1$ 个元素，答案反而更简单）。
- **偶数长度时中位数不唯一**：`nums[n/2]` 和 `nums[n/2-1]` 取哪个结果都一样；用「两端配对」写法可以完全绕过这个判断。
- **只在 lc 官方样例上验证不够**：`[1,10,2,9]` 恰好是偶数长度，用「取 `nums[n/2]` 直接算距离」也能过；但对 $\sum|a_i-t|$ 的写法要确认是「排序后取中位数」，不是「排序后取中间两个的平均」（取平均也能过这题，因为落在最优区间内，但拍成整数时会引入误差，别养成习惯）。
- 不要真的模拟「一个个加 1 减 1」，$a_i$ 到 $10^9$ 会直接超时。

## 总结

「让所有数变相等、每次加减 1」这类题先写成 $\sum|a_i-t|$，然后问一句「$t$ 取什么最小」——答案是中位数，因为绝对值和是凸的。排序后不必求中位数，直接两端配对相减求和，奇数长度和偶数长度都能自动成立。
