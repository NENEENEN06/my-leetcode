# 3644. Maximum K to Sort a Permutation

- Difficulty: Medium
- Topics: Array, Bit Manipulation
- Language: C++
- 题目链接: https://leetcode.cn/problems/maximum-k-to-sort-a-permutation/

## 题目

给定 `0 ~ n-1` 的一个排列，只有当两个元素的按位与**恰好等于 k** 时才允许交换它们，求能把数组排成升序的最大 k；已经有序则返回 0。

## 我的思路

关键在于「谁必须参与交换」。用交换排序一个排列时，只要某个元素不在它的目标下标上（`nums[i] != i`），它就必须被换走至少一次——因为换位只发生在两个元素之间，没参与过交换的元素位置不会变。

一次合法交换里两个数 `u`、`v` 满足 `u & v == k`，而按位与只会越与越小，所以 `k` 的每一位都必须是 `u`、`v` 里都有的位，也就是 `k` 是两者的**位掩码子集**。于是：

- `k` 必须是**每个**错位元素的位子集 ⇒ `k` 至多是所有错位元素的按位与。
- 这个上界能取到（官方提示就是这句：对所有不在正确位置上的元素取按位与），所以答案就是它。

代码里用一个变量边走边与：初值取 `-1`（全 1，与任何数相与都不改变它），扫到错位元素就 `ans &= nums[i]`。扫完 `ans` 还是 `-1` 说明一个错位的都没有，即数组本来就有序，按题意返回 0。

## 代码

```cpp
// 3644. Maximum K to Sort a Permutation
// 答案 = 所有错位元素的按位与：k 的每一位都必须同时出现在参与交换的两个数里，
// 而每个错位元素至少要参与一次交换，所以 k 是它们的公共位子集；这个上界可达到。
class Solution {
public:
    int sortPermutation(vector<int>& nums) {
        int ans = -1;   // 全 1，相与不改变任何数；扫完仍为 -1 说明本来就有序
        int n = nums.size();
        for (int i = 0; i < n; i++) {
            if (nums[i] != i) {
                ans &= nums[i];
            }
        }
        return (ans == -1) ? 0 : ans;
    }
};
```

## 代码分析

- 正确性：正确。我在本机用真 BFS（逐个 k 试，状态是排列本身）把 `n <= 6` 的全部排列对拍过，排除「本来就有序」这一特例后零不一致
- 关键实现：`ans = -1` 一物两用——既是按位与的单位元，又当「没有错位元素」的哨兵，省掉一个计数器
- 潜在 Bug：`ans == -1` 这个判据依赖元素非负（`0 <= nums[i] <= n-1`）。若值域含负数，`-1` 可能被真正与出来，就分不清「有序」和「结果是 -1」了；本题约束下安全
- 可以改进的地方：也可以先找第一个错位下标再起手，或者用 `bool sorted` 标志，读起来更直白，但会多一个变量

## 复杂度

- 时间复杂度：O(n)，一趟扫描，每个位置一次比较 + 最多一次按位与
- 空间复杂度：O(1)

## 易错点

- **已排序要返回 0**，不能让 `ans` 的初值 `-1` 漏出去
- 条件是 `nums[i] AND nums[j] == k`，**恰好等于**，不是「至少 k」。所以不能把 k 往上抬，也不能随手取「所有错位值与」之类的上界
- `ans` 初值必须是 `-1`（全 1）；写成 0 就永远只会得到 0
- 只统计错位元素：已就位的元素不需要动，把它们也算进按位与会把答案压小

## 总结

「交换条件是按位与等于定值」这类题，切入点永远是「哪些元素必须参与交换」——参与者的位必须包含 k，于是 k 的上界就是一个按位与。这类题里 `-1` 当作按位与的单位元和哨兵，是很顺手的一手。
