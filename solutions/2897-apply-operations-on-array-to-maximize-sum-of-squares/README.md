# 2897. Apply Operations on Array to Maximize Sum of Squares

- Difficulty: Hard
- Topics: Bit Manipulation, Greedy, Array, Hash Table
- Language: C++
- 题目链接: https://leetcode.cn/problems/apply-operations-on-array-to-maximize-sum-of-squares/

## 题目

给定数组 `nums` 和正整数 `k`。可以任意次选择两个不同下标 `i`、`j`，同时把 `nums[i]` 变成 `nums[i] AND nums[j]`、`nums[j]` 变成 `nums[i] OR nums[j]`。操作结束后从数组中选 `k` 个元素，求平方和的最大值（对 $10^9+7$ 取模）。

## 我的思路

核心是先把「操作」翻译成「**比特的搬运**」，再把问题变成「资源分配」：

- 对任意一位看 `AND` / `OR` 的效果：两数该位相同则不变；不同则一个变成 0、一个变成 1。也就是说，**每种位上 1 的总个数在操作前后守恒**，但每个 1 可以自由地从一个元素搬到另一个元素（谁持有没有限制）。
- 于是可以无视元素身份，只统计每一位上有多少个 1：`cnt[j]` = 第 `j` 位上 1 的个数，它同时也是可自由分配的「原料」。
- 接下来是要把 `cnt` 这批原料组装成 `k` 个数，使平方和最大。数学上：设 $a>b$，把 $c$ 从 $b$ 挪给 $a$，得到 $(a+c)^2+(b-c)^2 = a^2+b^2+2c(a-b)+2c^2 > a^2+b^2$。所以**越集中越好**：高位要优先堆到同一个数上，做出尽量大的几个数。
- 具体做法：重复 `k` 轮，每轮构造一个数 `tmp`，把当前仍有余量的每一位都取一个 1 进来（`cnt[j]--`）。这样第 `t` 轮造出的数正好拿到每一位上的第 `t` 个 1，等价于「每一位的 1 按从高到低依次分给第 1、2、…、k 大的数」，正是贪心要求的分配。
- 关键变量：`cnt[32]`（各位 1 计数，同时充当剩余可取用的原料）、`tmp`（当前构造出的数，`long long`）、`res`（答案累加并取模）。第 `t` 大的数必然拿到尽可能高的位，而高位贡献的增量远大于低位，「先集中、再下放」得到的就是最优解。

## 代码

```cpp
// 2897. Apply Operations on Array to Maximize Sum of Squares
// 操作只是把某一位从一个元素搬到另一个元素，所以每一位的「总份额」固定、可自由分配；
// 每轮尽量把每个还剩余的位都塞进同一个数（高位集中），平方和最大。
class Solution {
public:
    int maxSum(vector<int>& nums, int k) {
        int cnt[32] = {0};
        int res = 0;
        const int mod = 1e9 + 7;
        // cnt[i] 是第 i 位在所有元素中出现的次数，也就是这一位能分配的份额
        for (auto &num : nums) {
            for (int i = 0; i < 32; i++) {
                if (num & (1 << i)) {
                    cnt[i]++;
                }
            }
        }
        for (int i = 0; i < k; i++) {
            long long tmp = 0;
            for (int j = 0; j < 32; j++) {
                if (cnt[j]) {
                    cnt[j]--;
                    tmp += 1 << j;
                    tmp %= mod;
                }
            }
            res += (tmp * tmp) % mod;
            res %= mod;
        }
        return res;
    }
};
```

## 代码分析

- 正确性：正确。
- 关键实现：外层先按位统计 `cnt`，再用 `k` 轮「每个还有余量的位各取一个」的方式把比特集中到 `k` 个数里；因为每轮取的都是当前还能取的最高的那些位，所以第 1 个数最大、第 2 个次之，符合平方和最大化的贪心结构。
- 潜在 Bug：
  - `1<<j`（以及统计时的 `1<<i`）在 `j = 31` 时是**有符号 int 左移溢出**，属于 UB。本题 `nums[i] <= 1e9 < 2^30`，`cnt[31]` 恒为 0，`tmp += 1<<31` 不会被执行，`num & (1<<31)` 结果也恰好是 0，所以实际运行不受影响；但这是埋在代码里的隐患，换到 `nums[i]` 可能到 `2^31` 的题目上就会出错。
  - `res + (tmp*tmp)%mod`：`tmp < mod = 1e9+7`，`tmp*tmp < 1e18` 在 `long long` 内安全；`res` 的加法最大到约 $2\times10^9$，仍在 `INT_MAX`（2147483647）之内，属于「刚好不溢出」，余量只有约 1.5e8。
- 可以改进的地方：
  - 位判断统一写成 `(num >> i) & 1`，取位用 `1LL << j`，彻底避开移位 UB。
  - `res` 用 `long long`，或写成 `res = (res + tmp * tmp) % mod`，语义更清楚、也不用依赖「刚好不溢出」。
  - 统计最高位 `hi`（`nums` 中最大值的最高位），内层只循环到 `hi`，常数更小。

## 复杂度

- 时间复杂度：$O(32 \times (n + k))$。统计部分对每个元素扫 32 位；构造部分 `k` 轮、每轮扫 32 位。$n, k \le 10^5$ 时约 $6.4\times10^6$ 次操作。
- 空间复杂度：$O(32)$，即 $O(1)$（`cnt` 数组 + 常数个变量）。

## 易错点

- **不看操作细节，先找不变量**：`AND` / `OR` 这一步只是「1 在元素之间搬家」，每种位上 1 的个数始终不变。抓不到这个不变量，就容易去模拟操作，越陷越深。
- **贪心方向要证明**：不是「每个数都尽量大」，而是「尽可能集中」——因为 $(a+c)^2+(b-c)^2 > a^2+b^2\ (a>b,\ c>0)$。分散着填反而变小。
- **取模时机**：`tmp` 需要取模以免溢出，但 `tmp*tmp` 必须用 `long long` 算完再取模，不能先把 `tmp` 缩小到别的东西。
- **移位宽度**：`1 << 31` 是 UB，位上限不要写得比数据类型宽度还满。
- **边界**：`k = 1`（只取一个最大的数）、`k = n`（全部取用）、数组里有 0（本题 `nums[i] >= 1`，但思路里 0 不影响）。

## 总结

比特类题目的通用切口：先把位运算操作翻译成「位上 1 的个数守恒 + 1 可自由流动」，问题就从「数组操作」降维成「按位统计」；再对目标函数（这里是平方和）做单调性/凸性分析，得出「集中优于分散」的贪心，最后按位贪心构造出前 `k` 大的数。

## 复盘

- 这类题最容易想歪的地方：把「操作任意次」当成需要模拟的过程，而不是先想「操作能改变什么、不能改变什么」（不变量）。
- 关键突破点：意识到答案只取决于每一位 1 的总数，与其他一切无关。
- 下次看到「AND/OR 操作 + 最大化某目标」「位统计 + 构造若干个数」这类特征，先套这个模板：统计每位 1 的个数 → 证明集中更优 → 逐位贪心分配给前 `k` 个数。
