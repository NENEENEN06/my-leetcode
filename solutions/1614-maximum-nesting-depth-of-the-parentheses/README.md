# 1614. Maximum Nesting Depth of the Parentheses
- Difficulty: Easy
- Topics: String, Stack
- Language: C++
- 题目链接: https://leetcode.cn/problems/maximum-nesting-depth-of-the-parentheses/

## 题目
给定一个合法括号字符串 `s`（其中夹杂数字和运算符，如 `(1+(2*3)+((8)/4))+1`），返回括号的**最大嵌套深度**。

## 我的思路
不需要真的用栈——嵌套深度就是一个「计数器」的当前值：遇到 `(` 加一、遇到 `)` 减一，一路记录计数器的最大值即可。

- `curDepth` 是当前深度（也是未闭合左括号的数量）。
- 遇到 `(`：先 `++curDepth`，再与 `best` 比较取大（深度只会在这里上升，所以只需在 `(` 处更新最大值）。
- 遇到 `)`：`curDepth--`（题目保证括号合法，不会减到负数）。
- 其它字符（数字、运算符）一律忽略。

为什么正确：合法括号串里，任意位置上「已遇到 `(` 数 − 已遇到 `)` 数」正好等于该位置的嵌套深度；深度只可能在读到 `(` 的那一刻变大，所以在每个 `(` 处取 `max` 就覆盖了全部候选。

## 代码
```cpp
// 1614. Maximum Nesting Depth of the Parentheses
// 只需跟踪当前括号深度 curDepth，遇到 '(' 就自增并刷新历史最大值，数字不参与判断。
class Solution {
public:
    int maxDepth(string s) {
        int curDepth = 0;
        int best = 0;
        for (auto &ch : s) {
            if (ch == '(') {
                // 先自增再比较，best 记的是曾经到达过的最大深度
                best = (++curDepth > best) ? curDepth : best;
            }
            if (ch == ')') {
                // ')' 一定与之前某个 '(' 配对，深度回退一格
                curDepth--;
            }
        }
        return best;
    }
};
```

## 代码分析
- 正确性：正确。随机对拍用独立实现（先算前缀深度数组、再取所有 `(` 位置上的最大深度）作为参照，50000 组零不一致；经典用例 `(1+(2*3)+((8)/4))+1` → 3、`(1)+((2))+(((3)))` → 3、无括号串 → 0 全部吻合。
- 关键实现：把「嵌套深度」直接对应当前未闭合的 `(` 个数，一个整数就能替代显式栈；最大值只在 `++curDepth` 之后更新一次，写得很紧凑。
- 潜在 Bug：无。`if(ch=='(')` 与 `if(ch==')')` 两个并列判断互不冲突（一个字符不可能同时满足）。
- 可以改进的地方（都只是可读性）：
  1. `best=(++curDepth>best)?curDepth:best;` 把自增、比较、赋值塞在一个表达式里，读者要先在脑子里展开；写成 `++curDepth; best = best > curDepth ? best : curDepth;` 或 `best = max(best, ++curDepth);`（`<algorithm>`）更清楚。
  2. `for(auto &ch : s)` 用的是非 const 引用；这里只读不写，`for(char ch : s)` 更能表达意图（`s` 是值传递，改不改都不影响调用方，但语义上应只读）。
  3. `curDepth` 已经比原来的 `tmp` 达意；若想更短，`depth` 也行。

## 复杂度
- 时间复杂度：O(n)。每个字符一次比较，`(` 处多做一次取大。
- 空间复杂度：O(1)。只用两个整型变量，没有栈也没有数组。

## 易错点
- **只在 `(` 处更新最大值**：深度在 `)` 处只会变小，所以在 `(` 处取 `max` 就够了；反过来若在 `)` 处也取 `max`（在减之前）会得到同样的答案，但容易写错成减之后再取。
- **忘记 `++curDepth` 与取大的先后**：必须先自增再比较，否则最大深度会整体差 1（例如 `(1)` 会返回 0）。
- **把数字/运算符当成有效字符**：本题只需关心括号，其它字符忽略即可；试图解析表达式反而给自己找麻烦。
- **括号不匹配时的鲁棒性**：题目保证合法；若输入可能非法，`curDepth--` 会变成负数，需要自己加保护（`if(curDepth>0) curDepth--;`）。
- **以为必须用栈**：显式栈当然能做（压入深度），但本题只求最大值，一个计数器足够；多用一个容器只是浪费。

## 总结
「括号嵌套深度」这类问题的本质是**前缀计数**：把 `(` 记 +1、`)` 记 −1，深度序列就是它的前缀和，最大值只可能出现在加一的那一步。因此 O(n) 时间 + O(1) 空间即可，显式栈是多余的工具。这条思路同样适用于「最长有效括号」「括号匹配性检查」等题目。

## 复盘
- 容易想错的地方：一看到「括号」就想上栈；其实求深度只需要计数。
- 关键突破点：把「深度」重新定义为「当前未闭合左括号的数量」，问题立刻从数据结构题变成一行计数器。
- 下次看到什么特征应该想到这个算法：只需要**统计性**结论（最大深度、是否合法、最长合法长度）而不是具体配对关系时，先试前缀计数；只有当需要记录**配对位置**（如上一题 1190 要反转区间）时，才必须留下下标。
