# 3665. Twisted Mirror Path Count

- Difficulty: Medium
- Topics: Array, Dynamic Programming, Matrix
- Language: C++
- 题目链接: https://leetcode.cn/problems/twisted-mirror-path-count/

## 题目

一个 `m × n` 的 01 网格里，`0` 是空格、`1` 是镜子。机器人从 `(0, 0)` 出发去 `(m-1, n-1)`，每一步只能向右或向下；但**如果它要进入的格子是镜子，它会在进入前被反射**：向右撞镜子就转成向下、落在镜子正下方的格子，向下撞镜子就转成向右、落在镜子正右方的格子。反射后若落点还是镜子，就按「进入该镜子的方向」立刻再反射一次。反射导致出界的那条路径作废。求合法路径数对 `10^9 + 7` 取模。

## 我的思路

- 核心思想：还是「到每个格子的路径数」的网格 DP，只是**转移不再是相邻格**——每个格子有两条出边，各通往一面镜子链尽头的那个空格，落点要现场走一遍反射链才知道。
- 使用的数据结构：`ways[r][c]` 存到达 `(r, c)` 的路径数；`dRow/dCol` 两个数组把方向编号成 `0 = 向下`、`1 = 向右`，这样「转向」就是 `dir ^= 1`。
- 算法流程：
  1. `ways[0][0] = 1`，其余为 0，按行主序扫描每个格子。
  2. 对每个格子，分别以「向下」「向右」为第一步方向，模拟反射：沿当前方向前进一格；出界就说明这条路径无效；落点是空格就停下，这个格子就是终点；落点是镜子就把方向翻到另一个轴，再前进一格（这一步正好跳过镜子，落到镜子正下 / 正右）。
  3. 把 `ways[r][c]` 累加到落点上取模。
  4. 返回 `ways[m-1][n-1]`。
- 为什么这样做：题目规定只能向右或向下，所以任何一次转移的落点行、列都不会小于出发点——**格子的偏序关系没被镜面破坏**，行主序扫一遍就能保证用 `ways[r][c]` 之前它已经收齐了所有来源的贡献，不需要拓扑排序。
- 关键状态 / 变量：`dir`（当前朝哪走）、`firstDir`（第一步选哪个方向，两个方向各对应一条不同的路径），`row/col`（反射链走到的位置）。
- 为什么能够得到正确答案：每条路径由「每个格子选哪个起始方向」唯一确定，且反射链是确定性的，所以不同选择之间不会重复计数；两条出边落到同一个格子时，路径在该格子之前确实是两条不同的路，累加正是要的效果。

## 代码

```cpp
// 3665. Twisted Mirror Path Count
// 每个格子分别试「向下」「向右」两个起始方向：撞到镜子就转向、跳过镜子继续走，
// 落到空格才算这一步的终点。行主序扫描保证支配格子的路径数先算完。
class Solution {
public:
    int uniquePaths(vector<vector<int>>& grid) {
        const int MOD = 1'000'000'007;
        const int rows = grid.size();
        const int cols = grid[0].size();

        // 方向编号：0 = 向下，1 = 向右；dir ^= 1 就是换到另一个轴
        const int dRow[2] = {1, 0};
        const int dCol[2] = {0, 1};

        // ways[r][c]：到达 (r, c) 的路径数
        vector<vector<int>> ways(rows, vector<int>(cols, 0));
        ways[0][0] = 1;

        for (int r = 0; r < rows; r++) {
            for (int c = 0; c < cols; c++) {
                for (int firstDir = 0; firstDir < 2; firstDir++) {
                    int dir = firstDir;
                    int row = r;
                    int col = c;
                    // 一路走，直到落在空格上（成功）或走出边界（这条路径无效）
                    while (true) {
                        row += dRow[dir];
                        col += dCol[dir];
                        if (row >= rows || col >= cols) {
                            break;
                        }
                        if (grid[row][col] == 0) {
                            break;
                        }
                        dir ^= 1;  // 落点是镜子：转向，并跳过这面镜子继续走
                    }
                    if (row >= rows || col >= cols) {
                        continue;
                    }
                    ways[row][col] = (ways[row][col] + ways[r][c]) % MOD;
                }
            }
        }
        return ways[rows - 1][cols - 1];
    }
};
```

## 代码分析

- 正确性：正确。本机对三个官方样例（答案 5 / 2 / 1）全部命中；另外把原始版本和现在这份改写版在 3000 组随机小网格（2×2 ~ 8×8，随机撒镜子）上对拍，结果逐组完全一致——说明这次整理只动了命名与循环结构，语义没漂。
- 关键实现：
  - **反射链用方向翻转表达**：`dir ^= 1` 把「向下 ↔ 向右」互换，和题目「向右撞镜子转成向下」是一一对应的，不需要写两套分支。
  - **先前进、后判断**：每次前进一格后才检查出界与是不是镜子，这样「跳过镜子」是自然结果——镜面本身永远不是落点。
  - **`ways[r][c] == 0` 的格子也照样扫**，累加 0 无害，省一次判断。
- 潜在 Bug：无明显错误。唯一要注意的是取模常量别写 `1e9 + 7`——它是 `double`，靠隐式转换才变成 `int`，开 `-Wconversion` 会报警；这里写成 `1'000'000'007`。
- 可以改进的地方：官方提示的做法是**先预计算跳转表** `go[i][j][0/1]`，把每个格子的两个落点算一次存下来，之后每轮 DP 直接查表，时间从 `O(m·n·(m+n))` 降到 `O(m·n)`，代价是多 `O(m·n)` 空间。本题 `m, n ≤ 500`，现在这种「边扫边算跳转」最坏情况实测 309 ms（500×500 全镜子），在限内够用，所以不预计算也合理——这是空间换时间的取舍，不是错。

## 复杂度

- 时间复杂度：`O(m·n·(m+n))` 最坏。每个格子两个方向，每个方向每次前进至少让行或列加一，反射链最长 `m+n` 步；网格里镜子越少链越短，全空格时退化成 `O(m·n)`。
- 空间复杂度：`O(m·n)`，只有 `ways` 表；没有额外的跳转表或递归栈。

## 易错点

- **反射之后落点可能还是镜子**：题目明确要求「立即再次反射，方向取决于进入方向」。只处理一层反射（撞一次镜子就跳出）会漏掉长链，官方样例 3 就是靠连续两次反射才得到答案 1。
- **反射出界要整条路径作废**，不是把这次转移当成「原地不动」或「跳过」——样例 3 里 `(0,0) → (1,0)[M] → (2,1)` 就是这种情况。
- **转移落点不一定在相邻行/列**，所以不能套「`ways[i-1][j] + ways[i][j-1]`」的老模板；但落点一定在同一行更右或同一列更下，行主序照样成立，这是能省掉拓扑排序的关键。
- **起点和终点保证是空格**（`grid[0][0] == grid[m-1][n-1] == 0`），不用特判起点自己在镜子上。
- `m, n ≥ 2`，所以 `ways[0][0]` 之外不会有「整行只有起点」的退化情形要处理。

## 总结

镜面只改变了**转移的落点**，没有改变「只能往右下走」这个偏序关系，所以这题仍是网格 DP，只是转移函数变成了「沿着反射链走到下一个空格」。这类题的两个通用套路：① 用方向编号 + 翻转把几何反射压成一个位运算；② 判断能不能用行主序时，看的是落点的行列是否单调不减，而不是看它是否相邻。

## 复盘

- 我哪里容易想错：一开始容易把「反射」理解成「在镜子处原地转向」，实际上镜子是被**跳过**的，机器人落在镜子正下方或正右方——差一格就整题对不上。
- 关键突破点：把「进入方向」当成状态、把「跳过镜子」当成一次额外的前进，反射链就能用一个 `while` 写干净。
- 下次看到什么特征应该想到这个算法：网格 + 「只能向右/向下」+ 每个格子的走法依赖它自己的值（障碍、传送、反射）——先确认偏序还在，在就可以直接 DP。
