# 3550. Smallest Index With Digit Sum Equal to Index
- Difficulty: Easy
- Topics: Array, Math
- Language: C++
- 题目链接: https://leetcode.cn/problems/smallest-index-with-digit-sum-equal-to-index/

## 题目
给定非负整数数组 `nums`，返回**最小的下标 i**，使得 `nums[i]` 的各位数字之和恰好等于 i；不存在这样的下标则返回 -1。

## 我的思路
从头扫描，边扫边算当前元素的数位和，一旦命中立刻返回——因为是从小到大遍历，第一个满足的下标就是答案。

- 数位和用「除十取余」循环拆位：`num += nums[i] % 10; nums[i] /= 10;` 反复剥掉最低位，直到数字变成 0。
- 拆完立刻比对 `num == i`，成立就 `return i`（无需继续扫描）。
- 全部扫完仍未命中则 `return -1`。

关键点：**下标本身就是比较对象**，所以不能一边拆位一边用 `i` 参与别的运算；另外下标与数位和都是小整数，`int` 足够。

## 代码
```cpp
class Solution {
public:
    int smallestIndex(vector<int>& nums) {
        int n=nums.size();
        for(int i=0;i<n;i++){
            int num=0;
            while(nums[i]){
                num+=nums[i]%10;
                nums[i]/=10;
            }
            if(num==i){
                return i;
            }
        }
        return -1;
    }
};
```

## 代码分析
- 正确性：正确。逻辑上等价于「对每个 i 求 nums[i] 的数位和再比较」，随机对拍（含 0、含 1000 等边界）与独立实现零不一致；早退（命中即返回）保证了返回的是最小下标。
- 关键实现：`while (nums[i])` 折半式的拆位循环；元素为 `0` 时循环体不执行，数位和自然是 0（符合定义），这一点容易误以为漏了。
- **潜在问题（不影响本题通过，但是坏习惯）**：`nums` 是按引用传入的，`nums[i] /= 10` 会**把原数组就地改成 0**。本题只调用一次、之后不再读 `nums`，所以结果正确；但一旦在同一数组上调用两次、或在调用后继续使用 `nums`，就会得到错误的数位和（第二次全部变成 0）。修法很简单：把 `int num=0;` 旁边加一行 `int x = nums[i];`，循环里拆 `x`：
  ```cpp
  int x = nums[i], num = 0;
  while (x) { num += x % 10; x /= 10; }
  ```
  实测对比：同一数组连调两次，当前写法第二次把 `[1,10,2]` 全变成 0 导致结果改变；改成局部副本后两次结果一致。
- 也可以改进的地方：`int n=nums.size();` 若改成 `size_t` 可避免 signed/unsigned 警告；数位和规模很小，无需其它优化。

## 复杂度
- 时间复杂度：O(n · log₁₀(max(nums[i]))) 。每个元素最多处理 4 位（`nums[i] ≤ 1000`），因此实际是 O(n)；最坏情况下要扫完整个数组（无解时）。
- 空间复杂度：O(1)。只用了一个数位和累加器。

## 易错点
- **就地修改入参**（本题最大的坑）：拆位时用 `nums[i] /= 10` 会把数组清零，属于「能通过但不可复用」的写法；用局部副本 `x = nums[i]` 拆位才是干净的。LeetCode 里很多题会在同一测试进程里复用数组，习惯不好容易在别的题上翻车。
- **`while (nums[i])` 与 0**：元素是 0 时循环不执行，数位和为 0；这**不是** bug，但读代码的人容易以为是漏算，写注释更清楚。
- **数位和与下标比较方向写反**：题目要求「数位和 == 下标」，不是「下标 == 元素值」。
- **忘记早退**：如果要找最小下标，命中后必须立刻返回；把 `return i` 写成记录再继续扫，最后可能返回最大下标。
- **负数**：本题约束 `0 ≤ nums[i] ≤ 1000`；若数组可能有负数，`% 10` 会得到负余数（C++ 中 `-12 % 10 == -2`），必须先取绝对值。
- **越界风险无**：拆位循环对任何非负整数都收敛，不会死循环。

## 总结
「拆位求数位和」是入门级套路（`while (x) { s += x % 10; x /= 10; }`），但这题有个值得记住的工程细节：**拆位会消耗掉被拆的数，所以千万不要直接拆入参数组**，先拷贝到局部变量。算法层面就是一次 O(n) 线性扫描 + 命中即返回。

## 复盘
- 容易想错的地方：把「数位和」写成字符串转换（`to_string` 再累加）虽然也对，但没必要；另一个常见错是就地拆 `nums[i]` 而不自知。
- 关键突破点：识别出「最小下标」等价于「从左到右第一个命中」，于是可以边扫边算、命中即返回，不需要额外存储。
- 下次看到什么特征应该想到这个算法：需要按位处理数字（数位和、回文、数码统计）的题，一律先想「除十取余」循环，并顺手确认会不会破坏入参。
