# 3963. Create Grid With Exactly One Path

- Difficulty: Easy
- Topics: Matrix
- Language: C++
- 题目链接: https://leetcode.cn/problems/create-grid-with-exactly-one-path/

## 题目

给定 `m` 和 `n`，构造任意一个 `m × n` 的网格，格子只能是 `'.'`（可走）或 `'#'`（障碍），要求从左上角 `(0, 0)` 走到右下角 `(m-1, n-1)`、每一步只能向右或向下时，恰好存在**一条**合法路径。答案不唯一。

## 我的思路

- 核心思想：与其统计路径数，不如把网格「掐」成一条形状最简单的走廊——先竖着走到底，再横着走到终点，其余格子全部封死。
- 使用的数据结构：二维字符数组 `grid`，初始全填 `'#'`。
- 算法流程：
  1. 整个网格初始化为 `'#'`（先假设全是障碍）。
  2. 把第 `0` 列（`grid[i][0]`，`0 ≤ i < m`）改成 `'.'`，打开一条向下的通道。
  3. 把最后一行（`grid[m-1][i]`，`1 ≤ i < n`）改成 `'.'`，打开一条向右的通道。
- 为什么这样做：两条通道在 `(m-1, 0)` 处对接，形成唯一一条 L 形走廊；走廊上的每一格只有一个可走的下一格，走廊外全是障碍。
- 关键状态 / 变量：无需额外状态，`grid` 就是答案本身。
- 为什么能够得到正确答案：从 `(0,0)` 出发，在到达最后一行之前，右侧永远是 `'#'`，只能向下；到达最后一行后，除了向右没有别的去处（下方出界、上方已走过）。因此每条合法路径都被迫沿这条走廊走完，路径数恰好为 1。

## 代码

```cpp
// 3963. Create Grid With Exactly One Path
// 只留一条 L 形通道：第一列全通、最后一行全通，其余格子全封死，于是路径唯一。
class Solution {
public:
    vector<string> createGrid(int m, int n) {
        vector<string> grid(m, string(n, '#'));
        // 第一列留空：从左上角只能一路向下走
        for (int i = 0; i < m; i++) {
            grid[i][0] = '.';
        }
        // 最后一行留空：走到底后只能一路向右走；第 0 列刚填过，从 1 开始即可
        for (int i = 1; i < n; i++) {
            grid[m - 1][i] = '.';
        }
        return grid;
    }
};
```

## 代码分析

- 正确性：正确。`m = 1` 时第 0 列与最后一行是同一行，整行全 `'.'`，只有唯一一条横着走的路；`n = 1` 时第二个循环不执行，整列全 `'.'`，只有唯一一条竖着走的路。
- 关键实现：第二个循环从 `i = 1` 开始，避免把已经填好的 `grid[m-1][0]` 重复赋值（写 `0` 也无害，只是多一次覆盖）。
- 潜在 Bug：无明显错误。注意 `grid` 必须初始化为 `'#'` 而不是 `'.'`，否则障碍处会额外产生大量路径。
- 可以改进的地方：无。本题是构造题，任意合法答案都算通过，这条 L 形走廊已经是通用、最直观的构造。

## 复杂度

- 时间复杂度：O(m·n)，初始化网格占主导；两个填充循环合起来只有 O(m + n)。
- 空间复杂度：O(1) 额外空间（不计返回的 `m × n` 网格本身）。

## 易错点

- **忘记初始化成 `'#'`**：用 `vector<string>(m, string(n, '.'))` 再挑选着封堵，很容易漏封，路径数立刻大于 1。
- **`m = 1` 或 `n = 1` 的边界**：单行 / 单列时走廊退化成一条直线，代码里的两个循环恰好都不越界、不重复。
- **想成「数路径」**：题目要的是构造，不需要动态规划计数；看到「构造任意一个满足条件的结构」就该先想「把别的出路全堵死」。

## 总结

构造类题目的常见套路：不去精确计算，而是把答案设计成「独一无二」的形状——这里是一条 L 形走廊。先把场景限制到只剩一种走法，唯一性就自动成立了。

## 复盘

- 我哪里容易想错：容易去想「怎么让路径数恰好为 1」的判定公式，而这类题只需要造一条走廊、其余封死。
- 关键突破点：只要保证走廊上每一格的可走邻居只有「合法的下一格」，路径必然唯一。
- 下次看到什么特征应该想到这个算法：「构造任意一个满足条件的网格 / 序列」+「恰好」这个限定词。
