# 2567. Minimum Score by Changing Two Elements

- Difficulty: Medium
- Topics: Array, Greedy, Sorting
- Language: C++
- 题目链接: https://leetcode.com/problems/minimum-score-by-changing-two-elements/

## 题目

数组的「得分」定义为最大值与最小值之差。允许**改两个元素**（改成任意整数），求能让得分变得多小。

## 我的思路

- **核心思想**：排序后只看两头。要把「最大值 − 最小值」压小，能改的两个元素一定用在「砍掉最大的几个」或「填平最小的几个」上，所以只需要考虑三种组合。
- **为什么只有三种**：
  - 改最小的两个 → 新最小值是 `nums[2]`，最大值仍是 `nums[n-1]`，得分 `nums[n-1] - nums[2]`；
  - 改最大的两个 → 得分 `nums[n-3] - nums[0]`；
  - 一边一个 → 得分 `nums[n-2] - nums[1]`。
  - 其他改法（比如改中间的元素）不会影响极差，只会更差，不可能更优。
- **边界**：`n <= 3` 时，能把除一个以外的都改掉（或三数全改），得分必然是 0，直接返回。

## 代码

```cpp
class Solution {
public:
    int minimizeSum(vector<int>& nums) {
        int n = nums.size();
        if (n <= 3) {
            return 0;
        } else {
            sort(nums.begin(), nums.end());
            // 改两个元素只可能砍掉「一头一尾」或「同一头两个」
            return min(nums[n - 2] - nums[1], min(nums[n - 3] - nums[0], nums[n - 1] - nums[2]));
        }
    }
};
```

## 代码分析

- 正确性：力扣站内已 AC（本机未复跑，代码取自该次 Accepted 提交）。前面两次 WA 是没考虑到三种组合里的某一种。
- 关键实现：三种候选写成嵌套 `min`，一次算出；排序是必要前提，否则拿不到「第几小/第几大」。
- 潜在 Bug：无。`n <= 3` 的提前返回挡住了 `n - 3` 变负的越界风险。
- 可以改进的地方：外层 `if/else` 可以去掉 `else`（提前 `return 0` 之后走不到），但留着不影响正确性；`nums` 是引用，排序会改动入参——本题无所谓。

## 复杂度

- 时间复杂度：`O(n log n)`，排序是瓶颈，其余是常数比较。
- 空间复杂度：`O(log n)`，即 `std::sort` 的递归栈开销。

## 易错点

- **只想到「改最大的两个」**是最常见的错，我前两次 WA 就是漏了「改最小两个」和「一头一尾」。
- `n <= 3` 必须单独处理，否则下标会负数。
- 改两个元素是「能改」不是「必须改」，所以结果不会比原差距更大。

## 总结

- 极差问题先排序，再问「改动会影响哪几个下标」——能把候选压到常数个。
- 这类题的关键不是写代码，而是**把改动空间枚举全**：两个改动点落在「前 k 个/后 m 个」的组合只有三种。

## 复盘

- 先 WA 两次，说明直觉上容易只盯最大值；正确做法是画一个排序后的数轴，标出「谁在决定 min、谁在决定 max」，再数组合。
- 以后遇到「最多改 k 个使极差最小」，先想 k+1 种组合这个模式。
