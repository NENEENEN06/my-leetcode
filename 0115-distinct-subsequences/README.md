# 0115. Distinct Subsequences

- Difficulty: Hard
- Topics: String, Dynamic Programming
- Language: C++
- 题目链接: https://leetcode.cn/problems/distinct-subsequences/

## 题目

给定两个字符串 `s` 和 `t`，统计 `s` 的所有子序列中等于 `t` 的个数。子序列是指删除若干字符（也可以一个不删）后，剩余字符保持原有相对顺序得到的字符串。

## 我的思路

- 核心思想：二维动态规划。`dp[i][j]` 表示用 `s[0..i]` 能构造出多少个等于 `t[0..j]` 的子序列。
- 使用的数据结构：二维 `vector<vector<unsigned long long>> dp`，大小为 `sLen × tLen`。
- 算法流程：
  1. 先填第一列 `dp[i][0]`：用一个计数器记录 `t[0]` 在 `s[0..i]` 中出现的次数，`dp[i][0]` 存这个次数。它正好等于用 `s[0..i]` 构造单字符目标 `t[0]` 的子序列数。
  2. 对 `i` 从 1 到 `sLen-1`、`j` 从 1 到 `tLen-1`：
     - 先继承"不用 `s[i]`"的情况：`dp[i][j] = dp[i-1][j]`。
     - 若 `s[i] == t[j]`，则可以用 `s[i]` 去匹配 `t[j]`，把 `dp[i-1][j-1]`（用 `s[0..i-1]` 构造 `t[0..j-1]` 的方案数）累加进来。
  3. 返回 `dp[sLen-1][tLen-1]`。
- 为什么这样做：对每个 `s` 的前缀都在"是否用当前字符去匹配目标当前位"上做决策，从而枚举出所有可能的子序列组合。不匹配时方案数等于去掉 `s[i]` 后的前缀方案，匹配时还要加上"用更短前缀构造更短目标"的方案。
- 关键状态 / 变量：`dp[i][j]`；以及第一列里的计数器 `j`——它并不是常规 DP 中的下标，而是用来累计 `t[0]` 出现次数的计数。
- 为什么能够得到正确答案：转移只依赖 `dp[i-1][j]` 和 `dp[i-1][j-1]`，递推关系正确。用样例 `s="rabbbit"`, `t="rabbit"` 手推可得到 3。

## 代码

```cpp
class Solution {
public:
   int numDistinct(string s, string t) {
       int sLen=s.size();
       int tLen=t.size();
       vector<vector<unsigned long long>>dp(sLen,vector<unsigned long long>(tLen,0));
       for(int i=0,j=0;i<sLen;++i){
           if(s[i]==t[0]){j++;}
           dp[i][0]=j;
       }
       for(int i=1;i<sLen;++i){
           for(int j=1;j<tLen;++j){
               dp[i][j]=dp[i-1][j];
               if(s[i]==t[j]){
                   dp[i][j]+=dp[i-1][j-1];
               }
           }
       }
       return dp[sLen-1][tLen-1];
   }
};
```

## 代码分析

- 正确性：正确。
- 关键实现：`dp[i][0]` 用"`t[0]` 从 `s[0..i]` 起出现的累计次数"作为单字符目标的方案数，省去了额外开一行/列；转移是 `dp[i][j] = dp[i-1][j] + (s[i]==t[j] ? dp[i-1][j-1] : 0)`。
- 潜在 Bug：单独看没有逻辑错误。两处需注意：一是函数返回 `int`，而 `dp` 用 `unsigned long long`。本题保证答案能放进 32 位有符号整数，所以隐式转换安全；若约束放宽会出现溢出。二是当 `tLen == 0` 或 `sLen == 0` 时会访问 `t[0]`、`dp[sLen-1]` 越界；本题约束两者都至少为 1，所以不会触发。
- 可以改进的地方：把二维表优化成一维滚动数组，空间降到 O(tLen)；`tLen > sLen` 时直接返回 0，省去无用计算；让 DP 元素类型与返回值一致（如 `long long` 或按题目保证用 `int`），避免不必要的类型混用。

## 复杂度

- 时间复杂度：O(sLen × tLen)。外层 `i`、内层 `j` 各遍历一次，第一列初始化是 O(sLen)。
- 空间复杂度：O(sLen × tLen)。主要占用二维 `dp` 表；用滚动数组可优化到 O(tLen)。

## 易错点

- 状态定义要清楚：`dp[i][j]` 是"子序列的个数"，而不是"是否匹配"。
- 第一列基准 `dp[i][0]` 是 `t[0]` 的累计出现次数，不是常见的恒为 1（那种写法对应空串基准）。两种都对本题成立，但别混用。
- 匹配时一定要累加 `dp[i-1][j-1]`；只取 `dp[i-1][j]` 会漏掉"用当前 `s[i]` 匹配 `t[j]`"这一整类方案。
- 答案可能很大，注意用足够宽的整型；本题保证在 32 位整数范围内。
- 仅当 `s[i] == t[j]` 时才累加，否则就是 `dp[i-1][j]`，不能无条件"沿用再加"。

## 总结

这本质是"两个序列的匹配计数"型 DP：决策就是"用不用 `s[i]` 去匹配 `t[j]`"，转移 `dp[i][j] = dp[i-1][j] + (s[i]==t[j]) * dp[i-1][j-1]`。它与编辑距离、最长公共子序列同源，但要区分"子序列"与"子串"，并记得用滚动数组把二维压成一维。

## 复盘

- 我哪里容易想错：容易把基准 `dp[i][0]` 按最普遍的"空串 = 1"来写，而这里是用"`t[0]` 出现次数"作为单字符目标的方案数；两种基准对本题都正确，但思路要统一。
- 关键突破点：理清 `dp[i][j]` 的定义后，转移非常自然——要么跳过 `s[i]`，要么用它匹配 `t[j]` 并把前缀的方案累加进来。
- 下次看到什么特征应该想到这个算法：给两个字符串，数其中一个串作为另一个串子序列出现的次数，优先想到这种"跳过 or 匹配"的二维 DP，并用滚动数组优化空间。
