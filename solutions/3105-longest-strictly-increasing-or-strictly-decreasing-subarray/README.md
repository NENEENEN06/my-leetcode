# 3105. Longest Strictly Increasing or Strictly Decreasing Subarray

- Difficulty: Easy
- Topics: Array
- Language: C++
- 题目链接: https://leetcode.cn/problems/longest-strictly-increasing-or-strictly-decreasing-subarray/

## 题目

给定整数数组 `nums`，返回其中**严格递增**或**严格递减**的最长连续子数组长度（子数组非空）。例：`[1,4,3,3,2]` → 2（`[1,4]` 或 `[4,3]`）；`[3,3,3,3]` → 1（没有严格变化）。

## 我的思路

- 核心思想：跑两趟双指针。第一趟只负责找最长的严格递增段，第二趟只负责找最长的严格递减段，两趟各自用一个左端点 `l` 记录当前单调段的起点，答案取两者的最大值。
- 数据结构：只有两个下标 `l`、`r` 和答案 `ans`，`nums` 只读，不需要额外数组。
- 算法流程（以递增那趟为例）：
  1. `l = r = 0`，循环中先更新 `ans = max(ans, r - l + 1)`（当前 `[l, r]` 就是一段单调区间）。
  2. `r++`，若已到数组末尾就退出。
  3. 检查 `nums[r]` 与 `nums[r-1]` 的关系：若**不满足**严格递增（`nums[r] <= nums[r-1]`），说明单调在 `r-1` 处断了，把 `l` 挪到 `r`，从 `r` 重新起算。
- 为什么这样做：一段区间只要相邻两两保持 `<`，它整体就是严格递增的；单调性一旦被 `nums[r]` 打破，任何包含 `r` 之前元素的更长区间都不可能再递增，所以左端点直接跳到 `r` 是安全且不丢解的。
- 关键变量：`l`（当前单调段的左端）、`r`（右端）、`ans`（历史最大值）；递减那趟只需把判据换成 `nums[r] >= nums[r-1]`。
- 为什么能够得到正确答案：每个 `r` 时刻的 `[l, r]` 都是以 `r` 结尾的最长单调段，遍历一遍就覆盖了所有以某位置结尾的最优解，取最大值即全局最长。

## 代码

```cpp
// 3105. Longest Strictly Increasing or Strictly Decreasing Subarray
// 两趟双指针：每趟维护一段单调区间的左端点 l 与右端点 r，
// 一旦 nums[r] 破坏当前单调性，就把 l 挪到 r（新区间从 r 重新起算）。
class Solution {
public:
    int longestMonotonicSubarray(vector<int>& nums) {
        int ans = 0;
        int n = nums.size();
        int l = 0, r = 0;
        // 第一趟：最长严格递增段，nums[r] <= nums[r-1] 就断开
        while (r < n) {
            ans = max(ans, r - l + 1);
            r++;
            if (r == n) {
                break;
            }
            if (nums[r] <= nums[r - 1]) {
                l = r;
            }
        }
        // 第二趟：最长严格递减段，nums[r] >= nums[r-1] 就断开
        l = 0;
        r = 0;
        while (r < n) {
            ans = max(ans, r - l + 1);
            r++;
            if (r == n) {
                break;
            }
            if (nums[r] >= nums[r - 1]) {
                l = r;
            }
        }
        return ans;
    }
};
```

## 代码分析

- 正确性：正确。本机与暴力解对拍（枚举所有子数组，逐对判严格递增/递减）——长度 1..7、值域 1..3 的**全部 3279 个数组**外加 3000 组随机数据，共 6279 组零差异；官方三个样例 2 / 1 / 3 全部复现。
- 关键实现：`ans` 的更新放在循环最前面、用当前的 `[l, r]` 更新，所以 `r` 到达 `n` 之前最后一次退出时不会漏掉以最后一个元素结尾的区间；`r++` 之后先判 `r == n` 再访问 `nums[r]`，避免越界。
- 潜在 Bug：无。注意判据是 `<=` / `>=`（严格单调），写成 `<` / `>` 会把平台上相邻相等的段也算进去；另外 `int n = nums.size()` 对本题规模安全，若换到超大输入要注意 `size()` 是无符号数。
- 可以改进的地方：可以合成一趟——同时维护当前递增段长度 `inc` 和递减段长度 `dec`，每步按 `nums[i]` 与前一个的比较决定哪个清零，`ans = max(ans, inc, dec)`，把 2n 次遍历压到 n 次。本题 `n ≤ 50`，两趟写法实测 `0 ms`，合并不带来实际收益，只是更紧凑。

## 复杂度

- 时间复杂度：O(n)，两趟各扫一遍常数工作。
- 空间复杂度：O(1)，只用几个下标变量。

## 易错点

- **“严格”二字**：相等就断，必须用 `<=` / `>=` 作为断开条件；用 `<` / `>` 会在 `[3,3,3,3]` 这类全平数组上错答成 4。
- **单元素数组**：`n = 1` 时循环只执行一次就 `r == n` 退出，`ans` 应为 1；如果先 `r++` 再更新 `ans`，就会漏成 0。
- **越界**：`r++` 之后必须先判 `r == n`，再读 `nums[r]`，否则最后一步访问 `nums[n]`。
- **两趟之间忘记重置 `l`**：第二趟开始前把 `l` 和 `r` 都归零（`r` 本来就停在旧值上）。
- **以为要连着看“先增后减”**：题目要的是**纯**递增或**纯**递减的一段，不是山脉数组，两趟分开扫正好对应。

## 总结

最长连续单调段的标准双指针模板：右端点一路前进，单调性一破就把左端点拽到断点处，全程 O(n)。这类题的考点几乎都落在“断开的判据”和“答案更新的时机”上——判据决定严格与非严格，更新时机决定单元素边界。

## 复盘

- 我哪里容易想错：容易在图省事时把判据写成 `<` / `>`，或者把 `ans` 的更新放在 `r++` 之后，前者错在相等元素、后者错在最后一个元素。
- 关键突破点：意识到“单调性被打破时，左端点直接跳到断点”不会丢失任何更优解，于是整个问题变成一趟滑动窗口。
- 下次看到什么特征应该想到这个算法：求“最长连续子数组”且性质是逐对可判的（递增 / 递减 / 差值不超过 k / 全相同……）——滑动窗口或同向双指针，单调性一旦破坏就移动左端。
