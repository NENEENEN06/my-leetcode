# 3499. Maximize Active Section with Trade I

- Difficulty: Medium
- Topics: String, Enumeration
- Language: C++
- 题目链接: https://leetcode.cn/problems/maximize-active-section-with-trade-i/

## 题目

给一个二进制串 `s`，`1` 表示活跃段、`0` 表示非活跃段。最多做一次「交易」：

1. 把一段被 `0` 包围的连续 `1` 改成 `0`；
2. 再把一段被 `1` 包围的连续 `0` 改成 `1`。

求操作后串里 `1` 的最大个数。注意把 `s` 看成两端各补一个 `1` 的 `t = "1" + s + "1"`，补的 `1` 不算进答案。`n ≤ 1e5`。

## 我的思路

一次交易真正改变的只有「中间那个 1 段」和「它左右两边的 0 段」：中间的 1 段先变 0，把左右两个 0 段并成一个大 0 段，这个大 0 段再整段变 1。中间的 1 段先删后加回来，净收益就是**左右两个 0 段长度之和**，`1` 的总数只增不减。

所以答案 = `1 的总数 + max(相邻两个 0 段长度之和)`。

实现上不需要真的存下所有 0 段，用两个滚动变量就够：

- `cntZero[0]` 存上一个 0 段的长度，`cntZero[1]` 存当前 0 段的长度；
- 扫到 0 时先把 `cntZero[1]` 挪进 `cntZero[0]`，再用内层 `while` 一次吞掉整段 0，得到本段长度；
- 每结束一段就用 `cntZero[0] + cntZero[1]` 更新 `cnt`（相邻两段 0 之间的 1 段天然存在，一定是个合法交易对象）。

最后 `cntZero[0] == 0` 说明整串里 0 段不超过一个（或者根本没有 0），就没有"被 0 夹住"的 1 段可动，直接返回 `1` 的总数；否则返回 `cnt + totalOne`。

## 代码

```cpp
class Solution {
public:
    int maxActiveSectionsAfterTrade(string s) {
        int totalOne=0;
        int n=s.size();
        vector<int>cntZero(2,0);
        int cnt=0;
        for(int i=0;i<n;i++){
            if(s[i]=='1'){
                totalOne++;
                continue;
            }
            cntZero[0]=cntZero[1];
            cntZero[1]=1;
            while(i+1<n&&s[i+1]=='0'){
                cntZero[1]++;
                i++;
            }
            cnt=max(cnt,cntZero[0]+cntZero[1]);
        }
        if(cntZero[0]==0){
            return totalOne;
        }
        return cnt+totalOne;
    }
};
```

## 代码分析

- 正确性：正确。四个官方样例全过，并与一份 `O(n²)` 暴力解（枚举被 0 包围的 1 段 → 枚举可变成 1 的 0 段 → 数 `1`）在长度 1~14 的全部 32766 个二进制串上对拍，结果完全一致。
- 关键实现：`cntZero[0] / cntZero[1]` 这对滚动变量把"上一个 0 段 / 当前 0 段"压成两个数，扫一遍就拿到所有相邻 0 段长度和，空间 `O(1)`。
- 潜在 Bug：`cntZero[0] == 0` 这个提前返回看着像"特判漏了情况"，其实站得住——它等价于"0 段个数 ≤ 1"，这时不存在左右都被 0 夹住的 1 段，交易无法进行，答案就是 `1` 的总数。反过来只要出现过两个 0 段，`cntZero[0]` 就必然被赋过非零值，不会误判。
- 可以改进的地方：内层 `while` 直接改 `i` 的写法能跑但不直观，也可以换成 `for` 里判断 `s[i] != s[i-1]`；另外这道题 `cntZero` 用 `int[2]` 比 `vector<int>` 更轻，但差别可以忽略。

## 复杂度

- 时间复杂度：`O(n)`，每个字符恰好被外层或内层访问一次。
- 空间复杂度：`O(1)`，只用了两个滚动变量和几个计数器（`vector<int>(2)` 算常数）。

## 易错点

- 净收益是"两个 0 段之和"，**不是**"两个 0 段之和减去中间 1 段的长度"——中间的 1 段变成 0 之后会被那个大 0 段一起变回 1，先减后加，抵消掉了。
- "被 0 包围"只在原串里对 1 段成立；但第二步找 0 段时的"被 1 包围"要用两端补了 `1` 的视角看，所以贴着收尾边界的 0 段也能被整段点亮（例如 `s = "01000"` 答案是 5，整串变 1）。
- 一次交易都没有合法对象时要返回 `1` 的总数，不能因为 `cnt = 0` 就当答案 0。像 `s = "0011"`，`1` 段顶在右边界、左边只有一个 0 段，交易做不了，答案就是 2。
- 全是 `1` 或全是 `0` 的极端串都要能过：`"111" -> 3`，`"0000" -> 0`。

## 总结

这类"改一段、净收益可拆分"的题，先做代数化简：把一次交易的账算清楚（本次净赚 `左零段 + 右零段`），答案就退化成"所有相邻两个同类段长度和的最大值"，一次线性扫描即可。边界和特判都交给"能不能找到合法交易对象"这一条来判断，比逐个 case 打补丁可靠。

## 复盘

- 卡点：写完主体后加了 `cntZero[0] == 0` 的提前返回，容易怀疑是不是多余的防御代码；实测它是必要的（全 1、只有一个 0 段的情形），而且不会遮蔽任何合法交易。
- 关键突破点：先想清楚"中间 1 段先变 0 再变 1，净贡献为 0"，收益只来自两侧 0 段。
