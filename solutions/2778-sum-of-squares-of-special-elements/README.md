# 2778. Sum of Squares of Special Elements
- Difficulty: Easy
- Topics: Array, Enumeration
- Language: C++ / Python
- 题目链接: https://leetcode.cn/problems/sum-of-squares-of-special-elements/

## 题目
给定长度为 `n` 的整数数组 `nums`。若某个元素的下标（**从 1 开始计数**）能整除 `n`，则称它是「特殊元素」。求所有特殊元素的平方和。

## 我的思路
直接枚举每个位置：第 `i` 个位置（0-based）对应 1-based 下标 `i+1`，判断 `n % (i+1) == 0`；命中就把 `nums[i]` 的平方累加。

本题唯一的坑就在这个 **0-based → 1-based 的换算**：判断条件里必须写 `i+1`，写成 `i` 会把下标 0 当成「能整除 n 的下标」直接算错。

## 代码

```cpp
class Solution {
public:
    int sumOfSquares(vector<int>& nums) {
        int res=0;
        int n=nums.size();
        for(int i=0;i<n;i++){
            if(n%(i+1)==0){
                res+=nums[i]*nums[i];
            }
        }
        return res;
    }
};
```

## 代码分析
- **正确性：通过**。25000 组测试（长度 1~12 随机数组 + 长度 1~1000 的全 100 数组）与「先枚举 n 的因子、再按 1-based 取数」的参照零不一致；官方两例全对（`[1,2,3,4]` → 21、`[2,7,1,19,18,3]` → 63）；特殊长度（n = 1、质数 7/11/97、完全平方数 16/100）逐个核对因子个数，全部吻合。
- **`i+1` 用得很准**：`n % (i+1) == 0` 是本题的核心判断，0-based 循环配 1-based 判断是正确写法。
- **平方不会溢出**：本题约束 `1 ≤ nums[i] ≤ 100`、`n ≤ 100`，极端情况（n=100 全 100）结果是 90000，远小于 `INT_MAX`。**但这是靠约束兜住的**——如果元素范围放大到 10⁴ 量级，`nums[i]*nums[i]*100` 就会越过 `int`（10¹⁰），那时 `res` 和乘法都要换 `long long`。
- **效率**：`O(n)` 枚举已经足够（n ≤ 100）。若把 n 放大到 10⁹ 而数组很小，更合适的做法是**枚举 n 的因子**（只试到 √n），因为「哪些下标会被命中」只取决于 n 的因子集合，与数组长度无关。

## 另一种写法（Python · `solution2.py`）

```python
class Solution:
    def sumOfSquares(self, nums: List[int]) -> int:
        return sum(nums[i]**2 for i in range(len(nums)) if len(nums)%(i+1)==0)
```

- 与上面的 C++ 版**逻辑完全一致**：`i+1` 做 1-based 换算、整除判断、累加平方；两版在同一批 2010 个用例上输出逐例相同（本机交叉核对，0 处不同）。
- 用生成器表达式 + `sum`，一行完成：`sum(... for i in range(len(nums)) if ...)`——生成器不建中间列表，额外空间 O(1)。
- 与 C++ 版一样，题解文件不能脱离判题机单独运行：`List` 由判题机的前置代码提供，本地跑要自己加 `from typing import List`。
- 小细节：条件里每次都调用 `len(nums)`（O(1)，无实质开销），提取成 `n = len(nums)` 可读性更好、也少一次属性查找。

## 复杂度
- 时间：O(n)——扫一遍数组，每个位置做一次取模。
- 空间：O(1)（不算输入本身）。
- 若改用「枚举 n 的因子」的思路，时间可降到 O(√n)，但在本题约束下没有实际差别。

## 易错点
- **0-based 与 1-based 混用**：判断必须用 `i+1`；这是本题最常错的一处。
- **漏掉最后一位**：`n` 本身永远是自己的因子，所以下标为 `n` 的元素（0-based 的 `i = n-1`）必然被选中，别在循环边界上写 `i < n-1`。
- **平方和的类型**：本题 `int` 够；元素值域变大时要换 `long long`（见上面的分析）。
- **把「下标」当「元素值」判断**：本题判断的是**下标**能否整除 n，与元素值本身无关（元素值只参与平方）。
- **空数组**：`n ≥ 1`，不会出现；若题目放宽要注意除零方向的问题（实际是取模，无害）。

## 总结
一题基础枚举：把 0-based 下标换算成 1-based 后判断整除，命中则累加平方。真正需要留意的只有两点——**下标基准**和**平方和的溢出余量**。

## 复盘
- 容易想错的地方：① 用 `i` 而不是 `i+1` 做整除判断；② 循环上界写错导致漏掉下标为 `n` 的元素；③ 想当然地认为「平方和一定不会溢出」（本题能过是因为约束限制，不是因为它安全）。
- 关键突破点：看出「特殊元素」的集合只由 n 的因子决定，因此也可以从因子出发枚举（O(√n)），这是从「枚举数组」到「枚举因子」的视角转换。
- 下次看到什么特征应该想到这个算法：题目要求「按下标与数组长度的整除关系筛选元素」时，直接枚举下标判定即可；若数组远小于长度量级，则改为枚举长度的因子更划算。
