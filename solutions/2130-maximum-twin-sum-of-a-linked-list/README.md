# 2130. Maximum Twin Sum of a Linked List

- Difficulty: Medium
- Topics: Linked List, Two Pointers, Stack
- Language: C++
- 题目链接: https://leetcode.cn/problems/maximum-twin-sum-of-a-linked-list/

## 题目

给定长度为偶数 `n` 的链表，第 `i` 个节点（0-indexed）与第 `n-1-i` 个节点互为「孪生」。求所有孪生节点对的节点值之和的最大值。

## 我的思路

- 核心思想：快慢指针一次遍历找到前半段，把前半段的值存进数组 `vec`，再让慢指针继续走完后半段，同时用下标从后往前取 `vec` 里对应的孪生值配对。
- 使用的数据结构：数组 `vec` 暂存前一半的节点值；两个指针 `node1`（慢）、`node2`（快）。
- 算法流程：
  1. 第一个 `while`：每一轮存下 `node1->val`，`node1` 走一步、`node2` 走两步，`n += 2`（因为走一轮覆盖两个节点，走完正好等于链表长度），`i++`。
  2. 第一个 `while` 结束时 `node1` 落在后半段第一个节点，`i == n/2`。
  3. 第二个 `while`：`res = max(res, node1->val + vec[n-1-i])`，`i` 继续自增，于是 `vec` 的下标从 `n/2-1` 递减到 `0`，正好与后半段从前到后一一配对。
- 为什么这样做：孪生关系是「前半段第 k 个 ↔ 后半段倒数第 k 个」；把前半段顺序存下来，后半段正序访问时只需让下标倒着走，就自然对上。
- 关键状态 / 变量：`vec`（前半段值）、`i`（跨两个循环复用的配对游标）、`n`（链表长度）。
- 为什么能够得到正确答案：`n` 用 `+=2` 统计出真实长度，配对下标 `n-1-i` 从 `n/2-1` 开始递减，覆盖全部 `n/2` 对且不重不漏。

## 代码

```cpp
// 2130. Maximum Twin Sum of a Linked List
// 快慢指针让 node1 停在链表中点，顺路把前半段的值按顺序存进 vec。
// 处理后半段时，下标 i 的孪生结点下标为 n-1-i，n 是链表总长，正好落回 vec 里。
class Solution {
public:
    int pairSum(ListNode* head) {
        int res = 0;
        int n = 0;
        int i = 0;
        vector<int> vec;
        ListNode* node1 = head;
        ListNode* node2 = head;
        while (node2 != nullptr) {
            // node2 一次走两步，它走到头时 node1 刚过半，n 也就攒到了全长
            vec.push_back(node1->val);
            n += 2;
            i++;
            node1 = node1->next;
            node2 = node2->next->next;
        }
        while (node1 != nullptr) {
            // i 从第一段接着数下来，此刻正是当前结点的全局下标，配对值在 n-1-i
            res = max(res, node1->val + vec[n - 1 - i]);
            i++;
            node1 = node1->next;
        }
        return res;
    }
};
```

## 代码分析

- 正确性：正确。本机 g++ 13.3 实际编译运行，与「数组两端对撞」参考解做 308 组对拍（含 n=2、全同值、值取上界 1e5 的边界，随机 n 到 400，另加 n=1000/9998/100000 的大样例），答案全部一致；开 ASan + UBSan 跑同一批也没有越界、未定义行为。n=1e5 时单次运行约 0.01s、进程峰值 7MB（含建链表的开销）。
- 关键实现：`n += 2` 而不是 `n++`——每轮快指针跨两个节点，这样循环结束时 `n` 才等于链表总长，后面 `n-1-i` 的偏移才算得对。
- 潜在 Bug：无明显错误。`i` 在两个循环之间连续自增，初看容易以为第二个循环要重置，其实正是靠它接着数才能让下标倒着走。
- 可以改进的地方：标准解法是「快慢指针找中点 + 反转后半段」，可以做到 O(1) 额外空间；当前写法用 O(n) 数组换来实现简单。

## 复杂度

- 时间复杂度：O(n)，第一个循环走 n/2 轮，第二个循环走 n/2 轮。
- 空间复杂度：O(n)，`vec` 存了前一半的 n/2 个值。

## 易错点

- `n += 2` 与 `i++` 的配合：`n` 是总长，`i` 是已配对数量，两者含义不同，别混。
- 第二个循环里 `i` 的初值必须接着第一个循环的结果（n/2），重置成 0 会让下溢成负数下标。
- 快指针写 `node2->next->next` 时，链表长度为偶数才有保证；本题题意保证了偶数长度。
- 值域 `1 <= Node.val <= 1e5`，最大和 2e5，`int` 足够。

## 总结

孪生对本质上是「前半段正序 ↔ 后半段倒序」的配对问题。抓住这一点，剩下的只是怎么在一趟扫描里把两半对齐——用数组暂存前一半、让下标倒着走，是最省脑子的写法。

## 复盘

- 我哪里容易想错：一开始容易把 `n` 当成节点计数、和 `i` 的语义混淆。
- 关键突破点：让 `i` 跨两个循环连续自增，把「配对序号」这件事交给一个变量管。
- 下次看到什么特征应该想到这个算法：链表里出现「第 i 个和第 n-1-i 个配对」，先想快慢指针分半，再想能不能不回改链表（数组 O(n)）或者反转后半段（O(1) 空间）。
