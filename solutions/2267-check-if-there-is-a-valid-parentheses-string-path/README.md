# 2267. Check if There Is a Valid Parentheses String Path
- Difficulty: Hard
- Topics: Array, Dynamic Programming, Matrix
- Language: C++
- 题目链接: https://leetcode.cn/problems/check-if-there-is-a-valid-parentheses-string-path/

## 题目
给定 `m × n` 的字符矩阵 `grid`（每格是 `'('` 或 `')'`），从左上角走到右下角，每步只能**向右或向下**。问是否存在一条路径，使得把路径上所有字符按顺序拼成的括号串是**合法括号串**。

## 我的思路
在网格上做 BFS，但状态不能只是「格子坐标」——还要带上**当前括号平衡数**，因为同一个格子在不同平衡下后续可行性完全不同。

- 状态 `(x, y, l)`：位于 `(x, y)`、已经读入的字符满足「左括号数 − 右括号数 = l」。
- 起始：`grid[0][0]` 必须是 `'('`，否则直接返回 false；否则推入 `(0, 0, 1)`。
- 转移：每步只走右 / 下两个方向，新平衡 `nl = l + (grid[nx][ny] == '(' ? 1 : -1)`；`nl < 0` 说明中途右括号多了，这条分支立即剪掉。
- 命中条件：到达 `(m-1, n-1)` 且 `nl == 0`（整串平衡、不欠不余）即返回 true。
- 去重：`vis[x][y][l]` 三维布尔数组，同一格同一平衡值只入队一次——这是把指数级路径枚举压成多项式状态数的关键。

为什么正确：合法括号串的判定等价于「任意前缀里 `)` 不超过 `(`，且总和为 0」，而 `l` 正是这个前缀量；因此在状态里只保留 `l` 就足够判断后续可行性，无需记住整个已走路径。右/下两方向的移动不改变这一点，所以到达终点的存在性判断是充分的。

平衡数的上界：路径共 `m+n-1` 个格子，`l` 最多就是 `m+n-1`，因此三维数组第三维取 `m+n` 就够（索引 `1 … m+n-1`）。

## 代码
```cpp
class Solution {
public:
    bool hasValidPath(vector<vector<char>>& grid) {
        struct Node{
            int x;
            int y;
            int l;
        };
        queue<Node>q;
        if(grid[0][0]==')'){
            return false;
        }
        q.push({0,0,1});
        int m=grid.size();
        int n=grid[0].size();
        int dx[]={0,1};
        int dy[]={1,0};
        vector<vector<vector<bool>>>vis(m,vector<vector<bool>>(n,vector<bool>(m+n,false)));
        vis[0][0][1]=true;
        while(!q.empty()){
            auto [x,y,l]=q.front();
            q.pop();
            for(int i=0;i<2;i++){
                int nx=x+dx[i];
                int ny=y+dy[i];
                if(nx>=m||ny>=n){continue;}
                int nl=l+(grid[nx][ny]=='('?1:-1);
                if(nl<0){continue;}
                if(nx==m-1&&ny==n-1&&nl==0){
                    return true;
                }
                else if(!vis[nx][ny][nl]){
                    q.push({nx,ny,nl});
                    vis[nx][ny][nl]=true;
                }
            }
        }
        return false;
    }
};
```

## 代码分析
- 正确性：正确。随机对拍用**暴力枚举全部路径**（小网格 DFS，最多 C(6,3)=20 条路径）作为参照，30000 组零不一致；1×1 这种「起点即终点」的退化情形也一致（返回 false，因为单个 `'('` 平衡为 1 ≠ 0）。
- 关键实现：
  1. 三维去重数组把「路径数」压成「状态数」，否则路径数是指数级的；
  2. `if(nx>=m||ny>=n) continue;` 只判右下越界即可，因为只往右/下走，不会出现负坐标；
  3. 终点判定放在入队之前（命中即返回），比出队时判定少一轮。
- 潜在 Bug：无。`vis` 第三维取 `m+n`，最坏平衡为 `m+n-1`，没有越界。
- 可以改进的地方（都是加速，不影响正确性）：
  1. **剪枝「剩余格数不足」**：若 `nl > (m-1-nx) + (n-1-ny) + 1`，剩下格子全是 `)` 也关不平，可以直接跳过；再加一层奇偶剪枝（`(剩余格数 - nl) % 2 != 0` 时不可能归零）。
  2. 终点格必须是 `)`（否则平衡无法归零），可先判 `grid[m-1][n-1] != ')'` 直接返回 false。
  3. BFS 用 `queue` 会带 `deque` 开销；本题只求存在性，深搜 + 记忆化（等价于本题的 DP）通常更快、内存更省。
  4. 结构体 `Node` 可以用 `tuple<int,int,int>` 或直接把三段编码进一个 `int`。

## 复杂度
- 时间复杂度：O(m · n · (m+n))。状态数上界是「格子数 × 平衡值数」= m·n·(m+n)，每个状态做常数次转移；本题 m, n ≤ 100，约 2×10⁶ 个状态。
- 空间复杂度：O(m · n · (m+n))。三维 `vis` 占约 2 MB（bool 数组），队列最坏同样量级。

## 易错点
- **状态里漏掉平衡数**：只用 `vis[x][y]` 去重是错的——同一格可能存在「平衡 1 能走通、平衡 3 走不通」的情况，按坐标去重会把可行分支误杀（或反之做出错误判断）。
- **第三维开小了**：平衡上界是 `m+n-1`，数组必须至少开 `m+n` 大小；开成 `n` 会越界（`m > 0` 时）。本解答用 `m+n` 恰好够。
- **忘了判起点**：起点是 `')'` 时任何路径的第一个字符就是右括号，直接非法；漏判会漏掉大量用例。
- **`nl < 0` 剪枝漏掉或写反**：写成 `nl <= 0` 会把「平衡恰好为 0 的中间状态」也剪掉，而那是合法的（只要终点也是 0）。
- **只走右/下**：本题不允许左/上移动；写成四个方向会让状态爆炸，也改变题意。
- **到达终点没检查 `nl == 0`**：只判断「到终点了」会误判为 true（路径可能欠右括号）。
- **越界检查写成 `nx>m||ny>n`**：必须是 `>=`，否则访问 `grid[m][n]` 越界。

## 总结
「网格 + 括号 + 存在性」这类题的核心是**把隐式路径状态化**：括号合法性只依赖前缀平衡数 `l`，于是二维网格搜索升级为「坐标 + 平衡」的三维 DP / BFS，状态数从指数级路径降到 O(m·n·(m+n))。这一招在「网格上带累计约束的路径存在性」问题里是通式——把约束压缩成一个可增量更新的标量，塞进状态维度里即可。

## 复盘
- 容易想错的地方：先想「枚举所有路径再校验」（指数级），或者只按坐标去重导致漏解。
- 关键突破点：意识到括号串的合法性等价于「前缀平衡非负 + 末尾为 0」，因此状态只需带上平衡值；再加上「只往右下走」保证无环，去重数组就足以避免重复搜索。
- 下次看到什么特征应该想到这个算法：在网格 / DAG 上求路径的**存在性**，且约束是「沿途累计量的某种条件」——一律考虑把累计量加入状态做记忆化搜索或 BFS。
