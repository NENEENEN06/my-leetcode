# 1267. Count Servers that Communicate

- Difficulty: Medium
- Topics: Array, Depth-First Search, Breadth-First Search, Union-Find, Matrix, Counting
- Language: C++
- 题目链接: https://leetcode.com/problems/count-servers-that-communicate/

## 题目

`m × n` 的 0/1 网格 `grid`，`1` 表示该格有服务器。两台服务器**在同一行或同一列**就算能通信（斜对角不算）。问能与至少一台别的服务器通信的服务器台数。

## 我的思路

- **核心思想**：不用真的建图。一台服务器能通信 ⟺ 它所在行或所在列的服务器数量 ≥ 2。所以先把每行、每列各有多少台服务器数出来，再逐台判定。
- **数据结构**：
  - `row[i]` / `col[j]`：第 `i` 行、第 `j` 列的服务器台数；
  - `servers`：所有服务器的坐标 `(i, j)`，遍历时用来取行列下标。
- **算法流程**：
  1. 扫一遍网格，`grid[i][j] == 1` 就 `row[i]++`、`col[j]++`，并把坐标塞进 `servers`；
  2. 再遍历 `servers`，`row[i] > 1 || col[j] > 1` 就把答案加一。
- **为什么正确**：通信关系是一行/一列内部的完全图，只要同行或同列存在第二台，两者直接相连；反过来，行列计数都是 1 的服务器四周没有任何同排的伙伴，必然孤立。所以「行计数 > 1 或列计数 > 1」与「能通信」等价。
- **关键状态**：全部是计数，没有中间状态需要回退，两趟扫描就结束。

## 代码

```cpp
// 1267. Count Servers that Communicate
// 先数出每行、每列各有多少台服务器，再逐台判「同行或同列还有第二台」，即 row[i] > 1 或 col[j] > 1。
class Solution {
public:
    int countServers(vector<vector<int>>& grid) {
        int res = 0;
        int m = grid.size();
        int n = grid[0].size();
        set<pair<int, int>> servers;   // 所有服务器的坐标 (i, j)，后面逐个判定
        vector<int> row(m, 0);         // row[i]：第 i 行的服务器数量
        vector<int> col(n, 0);         // col[j]：第 j 列的服务器数量
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] == 1) {
                    row[i]++;
                    col[j]++;
                    servers.insert({i, j});
                }
            }
        }
        // 同行或同列只要还有第二台服务器，这台就能通信
        for (auto [i, j] : servers) {
            if (row[i] > 1 || col[j] > 1) {
                res++;
            }
        }
        return res;
    }
};
```

## 代码分析

- 正确性：本机对拍通过——`1 ≤ m, n ≤ 8`、置 1 概率取遍 `0..99`（含全 0 网格，`99` 近似全 1）的随机网格 6000 组，与暴力解（把同行/同列连边、并查集求连通块、统计所在块大小 > 1 的点数）逐组比对，**零差异**；三个官方样例 `0 / 3 / 4` 全对。`250 × 250` 全 1 的最大规模只做性能测试（本机 15–30 ms，随负载波动），**未与参照解比对**——对拍覆盖的是小规模（≤ 64 格）。
- 关键实现：判定只依赖 `row` / `col` 两个计数，`servers` 只是第二趟遍历的「待判定清单」。
- 潜在 Bug：未发现问题。唯一隐式前提是 `m ≥ 1`（题面给了 `1 ≤ m, n ≤ 250`），否则 `grid[0]` 会越界；行列计数用 `int`，上限 250，不会溢出。
- 可以改进的地方：`servers` 是冗余的——第二趟直接再扫一遍 `grid` 取下标即可，省掉 `k` 个 `pair` 的堆内存和 `O(k log k)` 的插入（读完所有格子是 `Ω(mn)` 下界，所以最优也只到 `O(mn)`，省的是常数与内存）。

## 复杂度

- 时间复杂度：`O(mn + k log k)`，`k` 是服务器台数（`set` 插入）。把 `set` 换成二次扫描 `grid` 就是纯 `O(mn)`。
- 空间复杂度：`O(m + n + k)`——两个计数数组加上坐标集合；不算 `servers` 则只有 `O(m + n)`。

## 易错点

- **通信只沿同一行 / 同一列**，斜对角相邻不算，别当成四连通或八连通网格题。
- 孤立的单台服务器不计入答案；全 0 网格答案是 0。
- 不需要建图 / DFS / BFS——官方两条 hint 说的正是「存每行每列的数量」和「只数非孤立的服务器」。
- `row` / `col` 判定要用 `> 1`（含自己那一台），写成 `> 0` 会把所有服务器都算进去。

## 总结

- 「两两之间是否可行」这类关系，先找等价的可计数判据，往往能把 `O(k²)` 的建图降到 `O(mn)`；
- 行 / 列计数是矩阵题的高频套路：判重、判孤立、判唯一，都可以用它一次扫描拿到。

## 复盘

- 一眼看出是计数题，没有绕去并查集；暴力并查集只留在本机对拍里当判据。
- 顺手写的 `servers` 集合虽然多余，但让「第二趟怎么取下标」变得直观——记下这条可优化点，代码不动。
