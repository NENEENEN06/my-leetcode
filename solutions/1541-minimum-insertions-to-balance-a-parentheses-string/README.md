# 1541. Minimum Insertions to Balance a Parentheses String
- Difficulty: Medium
- Topics: String, Stack, Greedy
- Language: C++
- 题目链接: https://leetcode.cn/problems/minimum-insertions-to-balance-a-parentheses-string/

## 题目
给定只含 `(` `)` 的字符串，可以在任意位置插入字符，求**最少插入几个**，使得结果满足：

- 每个左括号 `(` 都必须配有**两个连续的右括号** `)`；
- 左括号必须出现在它的那两个 `))` 之前。

也就是合法串的语法是 `S → ε | S S | ( S ))`，最小非空单元是 `())`（长度为 3）。

**官方五个例子**（用来锚定规则）：

| s | 输出 |
|---|---|
| `"(()))"` | 1 |
| `"())"` | 0 |
| `"))())("` | 3 |
| `"(((((("` | 12 |
| `")))))))"` | 5 |

注意这跟普通括号匹配**不是一回事**：`"(())"` 在这里需要 **2** 次插入（每个 `(` 都要自己那两个 `)`），`"()"` 需要 **1** 次。

## 仓库里的三个版本

| 文件 | 思路 | 时间 | 额外空间 |
|---|---|---|---|
| `solution.cpp` | 作者原版：三个计数器 + 一个 flag | O(n) | O(1) |
| `solution2.cpp` | 优化版：单计数器 `need`（还欠的 `)` 数） | O(n) | O(1) |
| `solution3.cpp` | 另一种解法：栈，存每个未闭合 `(` 还欠几个 `)` | O(n) | O(n) |

三版都已用**状态机最短路**（见文末「验证方法」）穷举长度 0~14 的 32767 个串逐个对拍，结果全部一致，官方五例全对。

## 我的思路

原版（`solution.cpp`）用四个状态量交织完成这件事，先用状态轨迹看清各自含义。以 `"(()))"` 为例：

| 读入 | 事件 | l1 | l2 | l3 | flag |
|---|---|---|---|---|---|
| `(` | 新开一个 `(`，欠两个 `)` | 1 | 0 | 2 | 0 |
| `(` | 同上 | 2 | 0 | 4 | 0 |
| `)` | 最内层 `(` 拿到第一个 `)` | 2 | 0 | 4 | 1 |
| `)` | 最内层 `(` 收齐，欠数 −2 | 1 | 0 | 2 | 0 |
| `)` | 外层 `(` 拿到第一个 `)` | 1 | 0 | 2 | 1 |
| 收尾 | flag 仍为 1 → 欠数 −1 | 1 | 0 | 1 | 1 |

各变量职责：`l1` = 未闭合的 `(` 个数；`l3` = 还欠的 `)` 总数（每开一个 `(` 加 2，收齐一个减 2，收尾时按 flag ±1）；`l2` = 需要额外补的 `(` 个数；`flag` = 「刚读到某个 `(` 的第一个 `)`」或「刚读到一个还没结算的落单 `)`」。答案是 `l3 + l2`。

再看 `"))())("`：

| 读入 | 事件 | l1 | l2 | l3 | flag |
|---|---|---|---|---|---|
| `)` | 落单，标记待结算 | 0 | 0 | 0 | 1 |
| `)` | 给它补一个 `(` | 0 | 1 | 0 | 0 |
| `(` | 新开 | 1 | 1 | 2 | 0 |
| `)` | 拿到第一个 `)` | 1 | 1 | 2 | 1 |
| `)` | 收齐 | 0 | 1 | 0 | 0 |
| `(` | 新开 | 1 | 1 | 2 | 0 |

收尾时 flag 为 0，答案 = `l3 + l2` = 2 + 1 = 3 ✓（与官方一致）。

## 代码

```cpp
class Solution {
public:
    int minInsertions(string s) {
        int l1=0,l2=0,l3=0;
        int flag=0;
        for(auto &ch:s){
            if(ch=='('){
                if(flag){
                    if(l1==0){
                        l2++;
                        l3++;
                    }
                    else{
                        l3--;
                        l1--;
                    }
                    flag=0;
                }
                l1++;
                l3+=2;
            }
            else if(l1>0){
                if(flag){
                    l1--;
                    l3-=2;
                    flag=0;
                }
                else{
                    flag=1;
                }
            }
            else{
                if(flag){
                    l2++;
                    flag=0;
                }
                else{
                    flag=1;
                }
            }
        }
        if(flag){
            if(l1>0){
                l3--;
            }
            else{
                l3++;
                l2++;
            }
        }
        return l3+l2;
    }
};
```

## 代码分析

- **正确性：正确**。穷举长度 0~14 的全部 32767 个串 + 3000 个随机长串（长度 ≤ 40），与状态机最短路参照零不一致；官方五例全对。
- **可读性是真的差**，问题不在「用了三个变量」，而在**职责交叉**：
  - `l3` 在三处被不同方式修改：`(` 分支 `+2`、收齐 `)` 时 `-2`、结算 flag 时 `±1`——同一个变量同时表达「欠几个 `)`」和「补一个 `)`」两件事；
  - `l1`/`l2` 在不同分支既增又减，`flag=1` 在不同位置含义还不一样（有时代表「某个 `(` 的第一个 `)`」，有时代表「待结算的落单 `)`」）；
  - 收尾还要再分情况补一次，等于把同一套逻辑写了两遍。
  读代码的人很难在脑中重建不变量，改一处就得重新推全部分支——这正是你感觉像屎山的原因。功能上没错，但维护成本高。
- 建议：遇到这种「多个计数器互相补偿」的写法，先试着把状态压成**一个语义明确的量**（下面两版各是一种压法）。

## 优化版（solution2.cpp · 单计数器）

```cpp
class Solution {
public:
    int minInsertions(string s) {
        int ans = 0, need = 0;          // need：当前还需要的 ')' 个数
        for (char c : s) {
            if (c == '(') {
                // need 为奇数说明最内层 '(' 只收到一个 ')'，必须补一个才能开新括号
                if (need % 2 == 1) { ++ans; --need; }
                need += 2;              // 新 '(' 需要两个 ')'
            } else {
                --need;                 // 这个 ')' 抵掉一个需求
                if (need < 0) {         // 欠成负数：没有 '(' 可配，得补一个 '('（它欠两个）
                    ++ans;
                    need += 2;
                }
            }
        }
        return ans + need;              // 收尾：还欠的 ')' 全部补上
    }
};
```

**不变量**：`need` 始终表示「要闭合当前所有未完成的 `(`，还差几个 `)`」。

- `need` 为**偶数**：所有未完成的 `(` 都处在「一个 `)` 都还没拿到」的状态；
- `need` 为**奇数**：最内层的那个 `(` 已经拿到一个 `)`，下一个字符必须还是 `)`（否则就要插入）。

两条转移各对应一种「被迫的修补」：

- 读到 `(` 而 `need` 为奇数 → 先补一个 `)`（`++ans; --need;`），再开新括号 `need += 2`；
- 读到 `)` 后 `need < 0` → 这个 `)` 没有 `(` 可配，补一个 `(`（`++ans`），它带来的两个需求里被本字符抵掉一个 → `need += 2`（等价于 `need = 1`）；
- 扫完后 `need` 就是剩下的欠数，全部插入。

## 另一种解法（solution3.cpp · 栈）

```cpp
class Solution {
public:
    int minInsertions(string s) {
        vector<int> need;      // 栈里存每个未闭合 '(' 还欠的 ')' 个数（初始 2）
        int ans = 0;
        for (char c : s) {
            if (c == '(') {
                if (!need.empty() && need.back() == 1) {  // 上一个 '(' 只欠 1 个，必须先补上
                    ++ans;
                    need.pop_back();
                }
                need.push_back(2);
            } else {
                if (need.empty()) {                       // 没有 '(' 可配：补一个 '('
                    ++ans;
                    need.push_back(1);                    // 本字符充当它的第一个 ')'
                } else {
                    --need.back();
                    if (need.back() == 0) need.pop_back(); // 这一对 '(' 收齐了两个 ')'
                }
            }
        }
        for (int v : need) ans += v;   // 剩下的每个 '(' 还欠 1 或 2 个 ')'
        return ans;
    }
};
```

这版把「还欠多少」显式放在栈里，逐层对应嵌套结构：**每个 `(` 是一个待办项，欠数从 2 开始递减**。逻辑最直观，但空间 O(n)（栈深 = 嵌套层数）。适合用来给单计数器版做对照——两者其实在维护同一个量，只是一个用标量、一个用栈。

## 复杂度

| 版本 | 时间 | 额外空间 | 说明 |
|---|---|---|---|
| 原版 | O(n) | O(1) | 四个状态量都是常数 |
| 单计数器版 | O(n) | O(1) | 只有 `ans`、`need` |
| 栈版 | O(n) | O(n) | 栈深最多 n |

**注意**：所谓「优化」优化的是**可读性与出错概率**，不是复杂度——三个版本的时间/空间量级其实一样（前两版都是 O(1) 空间）。这一点值得记住：多数时候「优化代码」的第一目标是让人看懂，而不是让 Big-O 变小。

## 易错点

- **把本题当普通括号匹配**：普通匹配里 `"(())"` 合法，这里需要 2 次插入；`"()"` 普通匹配合法，这里需要 1 次。规则是「每个 `(` 配**两个连续** `)`」。
- **`need` 为奇数时的修补方向**（我最初就写反了）：必须 `++ans; --need;`，写成 `++need` 会让需求虚增——`")("` 会算成 6，正确答案是 4。
- **`)` 分支写成 `need == -1` 判断**：因为 `need` 每次只减 1，用 `need < 0` 更稳（本质上只可能等于 −1，但 `< 0` 不依赖这个前提）。
- **落单 `)` 的补法**：补「一个 `(`」和「一整对 `()`」在**当前字符**上代价相同（都是 2），但状态不同——补一个 `(` 会留下「已收到一个 `)`」的奇数状态，如果下一个字符是 `(` 就必须再补一个 `)`。状态机视角下两种选择都要考虑，这也是「贪心要配正确的不变量」的典型例子。
- **忘记收尾**：扫完后每个未闭合的 `(` 还欠 1 或 2 个 `)`，必须加上（原版用 flag 分情况处理，单计数器版直接 `ans + need`，栈版把栈内欠数求和）。
- **空串**：返回 0。
- **用 `int` 会不会溢出**：n ≤ 10⁵ 时答案最多约 2n，`int` 足够。

## 验证方法（为什么这次的参照可信）

计数器类写法最容易「看着对、实际差一点」，所以我没再用另一个计数器当参照，而是**直接按题目语法建了一个状态机，跑最短路**：

- 语法 `S → ε | S S | ( S ))`：每个 `(` 后面跟一个合法子串，再跟两个连续的 `)`；
- 状态 `(i, k, phase)`：已消费 `s` 的前 `i` 个字符、当前有 `k` 个未闭合的 `(`、`phase ∈ {0,1}` 表示最内层 `(` 是否已收到它的第一个 `)`；
- 动作：**消费** `s[i]` 代价 0（受 `phase` 约束：`phase=1` 时下一个字符必须是 `)`），**插入一个字符**代价 1；
- 目标：`(n, 0, 0)` 的最短代价即答案，用 Dijkstra 求。

这个参照只依赖题目原文的规则，不含任何「技巧」，穷举 32767 个短串 + 随机长串后，三个版本与它完全一致——所以结论是：**三个版本都正确**。

## 总结
本题的核心是把「每个 `(` 需要两个连续 `)`」这件事翻译成**一个语义清晰的欠数**：`need` 表示还差几个 `)`（偶数为正常、奇数为「最内层差第二个 `)`」）。所有插入都发生在两种「被迫」的情形里——该开新括号却发现上一个没闭合完、以及遇到没有 `(` 可配的 `)`——再加上收尾补齐剩余欠数，一趟扫描即可。

写多计数器版本时容易掉进「变量互相补偿」的陷阱：能跑对，但没人（包括三天后的自己）能一眼看出不变量。更稳的写法是**先写出不变量，再让代码只维护它**；实在绕不出来时，用状态机 + 最短路当参照来验证，比再写一个计数器可信得多。

## 复盘
- 容易想错的地方：① 按普通括号匹配的思路做（`"(())"` 会算错）；② 奇数欠数时把修补方向写反（我自己就先写错了一版，靠穷举对拍才发现）；③ 以为「补一个 `(`」一定优于「补一对 `()`」——在当前字符上代价相同，只有配合正确的不变量才不会算多。
- 关键突破点：意识到合法串的语法是 `S → ε | SS | (S))`，于是可以用 `need`（还欠几个 `)`）作为唯一状态量；`need` 的奇偶直接编码了「最内层是否已收到第一个 `)`」。
- 下次看到什么特征应该想到这个算法：题目规则是「每个 X 必须配**固定数量**的 Y，且 Y 要连续」时，优先想「用一个标量记录还欠多少个 Y」，奇偶/余数往往就编码了中间状态；如果直观写法绕不出来，先用状态机 + 最短路求出答案分布，再反推一个干净的不变量。
