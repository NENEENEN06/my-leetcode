# 921. Minimum Add to Make Parentheses Valid
- Difficulty: Medium
- Topics: String, Stack, Greedy
- Language: C++
- 题目链接: https://leetcode.cn/problems/minimum-add-to-make-parentheses-valid/

## 题目
给定一个由 `(` 和 `)` 组成的字符串，可以在任意位置插入括号，求**最少插入多少个**才能让字符串变成合法括号串。

## 我的思路
一次扫描，用两个计数器分别统计两种「配不上的括号」：

- `l1`：**已经读入但没有配对的左括号**数量（遇到 `(` 就加一）。
- `l2`：**找不到左括号可配的右括号**数量（遇到 `)` 且 `l1 == 0` 时加一）。
- 遇到 `)` 且 `l1 > 0` 时，就用掉一个未配对的 `(`：`l1--`。

最终 `l1 + l2` 就是答案：每个没配对的 `(` 需要在某处补一个 `)`（计 l1 次），每个没配对的 `)` 需要在它之前补一个 `(`（计 l2 次）。这两种补法是独立且必要的，所以相加即为最少插入数。

为什么这个下界能取到：只要在「未配对 `)`」前面补 `(`、在「未配对 `(`」后面补 `)`，得到的串就合法；而任何合法化方案都至少要为这些缺口各补一个括号，因此没有更少的方案。

## 代码
```cpp
class Solution {
public:
    int minAddToMakeValid(string s) {
        int l1=0,l2=0;
        for(auto &ch:s){
            if(ch=='('){
                l1++;
            }
            else if(l1>0){
                l1--;
            }
            else{
                l2++;
            }
        }
        return l1+l2;
    }
};
```

## 代码分析
- 正确性：正确。随机对拍用**前缀最小值的解析式**（未配对右括号 = `max(0, -minPrefix)`，未配对左括号 = 末态平衡 + 未配对右括号）这一完全不同的推导做参照，20 万组零不一致；经典用例 `"())"`→1、`"((("`→3、`"()"`→0、`"))("`→3、`"((())"`→1、`")("`→2 全部吻合。
- 关键实现：两个计数器分工明确（一个管「多出来的左」，一个管「多出来的右」），不需要真正用栈；`else if(l1>0)` 的优先级保证了「先试着配对、配不上才算缺口」的正确顺序。
- 潜在 Bug：无。无论输入是否合法都返回正确结果（不合法时得到的就是补全所需数量）。
- 可以改进的地方：仅可读性 —— `l1`/`l2` 改成 `open`/`close`（或 `needClose`/`needOpen`）语义更清楚；`for(auto &ch : s)` 用的是可变引用但只读，写 `for(char ch : s)` 更能表达意图。

## 复杂度
- 时间复杂度：O(n)。一次线性扫描，每个字符常数次操作。
- 空间复杂度：O(1)。两个整型计数器；对比之下，用栈的写法需要 O(n) 空间。

## 易错点
- **两个计数器含义搞混**：`l1` 是「多出的左括号」、`l2` 是「多出的右括号」，返回值是两者**相加**（每类缺口各补一个反向括号），不是相减也不是取最大。
- **遇到 `)` 时无条件减 `l1`**：必须先判断 `l1 > 0`，否则 `l1` 会变成负数，把「多余右括号」的数量算错（例如 `")("` 会得到 0）。
- **想去真的构造补全后的字符串**：题目只问数量，构造反而容易写错位置。
- **误以为要用栈**：栈能得到同样答案，但这里只需要两个计数，多用一个容器是浪费。
- **把 `l1 + l2` 写成 `abs(l1 - l2)`**：后者是「括号数量差」，与「需要插入的最少数」不是一回事（`")(("` 的数量差是 1，正确答案是 3）。
- **空串**：`s = ""` 返回 0，符合题意。

## 总结
「最少插入多少个括号才合法」的通用解法是**统计两类缺口**：扫描时维护未配对左括号数，遇到右括号先尝试配对，配不上就记一个「缺口」；扫完后未配对左括号数也是缺口。答案 = 两类缺口之和。这与「判断有效性」「最长有效括号」共享同一套前缀平衡（深度）的判据，只是各自关心不同的导出量。

## 复盘
- 容易想错的地方：想先删字符再补（题面只允许插入，且插入位置可以任意）；或者把两类缺口混成一个计数器。
- 关键突破点：意识到「合法化」的最小代价就是把每一处「配不上」独立补齐——右括号缺左就补左，左括号缺右就补右，互不影响，所以能分别计数后相加。
- 下次看到什么特征应该想到这个算法：题目问「最少增删几个字符使括号串合法」时，先想「统计不可配对的两类括号数量」；前缀平衡（深度）永远是这个家族的公共工具。
