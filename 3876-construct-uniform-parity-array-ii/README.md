# 3876. Construct Uniform Parity Array II

- Difficulty: Medium
- Topics: Array, Math
- Language: C++
- 题目链接: https://leetcode.cn/problems/construct-uniform-parity-array-ii/

## 题目

给定一个互不相同的整数数组 `nums1`，构造同样长度的 `nums2`，使其元素要么全为奇数、要么全为偶数。每个下标 `i` 可选 `nums2[i] = nums1[i]`，或 `nums2[i] = nums1[i] - nums1[j]`（`j != i` 且结果需 `>= 1`）。若能构造返回 `true`，否则返回 `false`。本题比 I 多了「只能减去更小的数」这一限制。

## 我的思路

- 核心思想：利用「只能减去更小的数」这一限制，先锁定全局最小值 `minx` 的奇偶性，再判断能否让所有数跟它一致。
- 使用的数据结构：无，只用两个变量 `minx` 和 `cnt`。
- 算法流程：
  1. 遍历数组，统计奇数个数 `cnt`，同时求出最小值 `minx`。
  2. 最小值 `minx` 没有更小的数可减，只能保留它自己，所以最终 `nums2` 必须和 `minx` 同奇偶。
  3. 若 `minx` 是奇数：任何偶数都可以减去 `minx`（更小）变成奇数，奇数保持不变，因此一定可行。
  4. 若 `minx` 是偶数：所有数最终必须是偶数；此时只要数组里有奇数就无法构造，因为最小的那个奇数没有更小的奇数可减，无法变成偶数。
- 为什么这样做：奇偶性只有两种，而最小值的奇偶性是被强制锁定的，剩下只需判断能否把所有元素“对齐”到它。
- 关键状态 / 变量：`minx`（全局最小值）、`cnt`（奇数个数）。
- 为什么能够得到正确答案：`minx` 奇数 → 全奇数可行；`minx` 偶数且无奇数 → 全偶数可行；`minx` 偶数且有奇数 → 最小奇数无法变偶，不可行。三种情况覆盖全部输入。

## 代码

```cpp
class Solution {
public:
   bool uniformArray(vector<int>& nums1) {
       int n=nums1.size();
       int minx=1e9;
       int cnt=0;
       for(int i=0;i<n;++i){
           if(nums1[i]%2){++cnt;}
           minx=min(minx,nums1[i]);
       }
       if(minx%2==0&&cnt){return false;}
       return true;
   }
};
```

## 代码分析

- 正确性：正确。
- 关键实现：`minx` 记录全局最小值，`cnt` 记录奇数个数；核心判断是 `if (minx % 2 == 0 && cnt) return false;`，其余情况返回 `true`。
- 潜在 Bug：无明显错误。`minx` 初始化为 `1e9` 在本题约束（`nums1[i] <= 1e9`）下是安全的；若数据范围更大则需要改成足够大的初始值或直接用 `nums1[0]`。
- 可以改进的地方：可以用 `allEven` 布尔变量替代 `cnt`，或直接用 `minx % 2 == 1 || 没有奇数` 来表达，逻辑更直白。

## 复杂度

- 时间复杂度：O(n)，只需一次遍历。
- 空间复杂度：O(1)，只用了常数个变量。

## 易错点

- 漏掉「`nums1[i] - nums1[j] >= 1`」这个限制：它意味着最小值只能保留自身，不能借更小的数来改变奇偶。
- 只看奇数个数而忽略最小值的奇偶性，容易在 `minx` 为偶数时误判为 `true`。
- `minx` 初始值要足够大，避免当真实最小值更大时初始化值错误地“保留”下来。
- 别把本题当成 I 直接 `return true`；II 存在 `[2,3]` 这类返回 `false` 的情况。

## 总结

这道题的关键洞察是：最小值没有更小的数可减，因此它的奇偶性决定了 `nums2` 的目标奇偶性。只要围绕最小值的奇偶性分类讨论，就能 O(n) 判断。

## 复盘

- 关键突破点：意识到最小值被锁定，且最小奇数无法变成偶数。
