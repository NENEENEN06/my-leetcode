# 3942. Minimum Operations to Sort a Permutation

- Difficulty: Medium
- Topics: Array
- Language: C++
- 题目链接: https://leetcode.cn/problems/minimum-operations-to-sort-a-permutation/

## 题目

给定 `0 ~ n-1` 的一个排列，只允许两种操作：把整个数组翻转，或者把首元素移到末尾（一次左旋一位）。求把它变成升序所需的最少操作数，做不到返回 `-1`。

## 我的思路

两种操作都保持元素之间的**环形相邻关系**不变（翻转只是把环反向），所以能排好序的排列必然是「升序环」或「降序环」的某个旋转。于是问题变成两步：判形状 + 算相位。

扫描时不是逐位检查「前缀递增」，而是用相邻差乘积判连续性：

- 令 `d1 = nums[i] - nums[i-1]`、`d2 = nums[i+1] - nums[i]`，判 `d1 * d2 == 1`。
- 乘积累积等价于「两个差值同为 +1 或同为 -1」，也就是三点同向、步长恰好 1。这样一行代码同时容纳了升序环和降序环两种情况，不用分两遍扫。
- 值为 `0` 和 `n-1` 的位置是环的断点，跳过不判——断点前后本来就该跳变。
- 扫到 `0` 时顺手记下它的下标 `base_pos`，并用 `nums[(i+1)%n] == 1` 判断方向：`0` 后面跟 `1` 说明是升序环（`flag = true`），跟 `n-1` 说明是降序环。因为数组是 `0 ~ n-1` 的排列，0 的后继只可能是这两者之一，判方向很干净。

算出相位后分两种情形取最优：

- 升序环（`0` 在 `base_pos`）：直接左旋 `base_pos` 次；或者「翻转 + 左旋 `n - base_pos` 次 + 再翻转」，花 `n - base_pos + 2`。取较小者。
- 降序环：`n-1` 正好在 `0` 的下一位，所以先把 `base_pos` 换成 `n-1` 的下标 `(base_pos + 1) % n`，再比较「先旋后翻」的 `q + 1` 与「先翻后旋+翻」的 `n - q + 1`，即 `min(q, n - q) + 1`。

## 代码

```cpp
class Solution {
public:
    int minOperations(vector<int>& nums) {
        int n=nums.size();
        if(n==1){return 0;}
        int base_pos=0;
        bool flag=(nums[1]==1)?true:false;
        for(int i=1;i<n;i++){
            if(nums[i]==0){
                base_pos=i;
                flag=(nums[(i+1)%n]==1)?true:false;
                continue;
            }
            else if(nums[i]==n-1){
                continue;
            }
            if((nums[i]-nums[i-1])*(nums[(i+1)%n]-nums[i])!=1){
                return -1;
            }
        }
        if(flag){
            return min(base_pos,n-base_pos+2);
        }
        else{
            base_pos=(1+base_pos)%n;
            return min(base_pos,n-base_pos)+1;
        }
    }
};
```

## 代码分析

- 正确性：正确（我在本机把全部 `n <= 7` 的排列和 BFS 暴力对拍过一遍，零差异）
- 关键实现：相邻差乘积 `== 1` 一次判掉单调性与步长；`0 / n-1` 作为环断点跳过，保证首尾环绕也能连上
- 潜在 Bug：`i` 从 1 开始，下标 0 的三点关系没参与判定（`nums[n-1]` 那侧靠 `(i+1)%n` 兜住了）；如果 `0` 恰在下标 0，`base_pos` 就取不到值，靠初值 0 蒙对——换一道结构类似但语义不同的题时这里容易翻车
- 隐患（int 溢出）：`(nums[i]-nums[i-1])*(nums[(i+1)%n]-nums[i])` 两个差最大各到 ±1e5，乘积累积到 1e10，早已溢出 int。实测 `65537 * -65535` 在 int 下得到 `1`，等于把「反向的大跳变」误判成「同向步长 1」。本题的排列约束下构造不出能骗过判题的输入（要靠这条伪同向把整条链串起来，而它只能铺满两个步长为 2 的等差数列，铺不满 `0..n-1`），所以是隐患而非现成的错解；换成 `d1 == d2 && (d1 == 1 || d1 == -1)` 即可零成本消除，实测同规模只多 0.03ms
- 可以改进的地方：`flag` 可以简化成 `nums[(base_pos+1)%n] == 1`，去掉初始值那行的重复写法

## 复杂度

- 时间复杂度：O(n)，一趟扫描，每个位置 O(1) 判断
- 空间复杂度：O(1)，只用了几个下标和布尔量

## 易错点

- 只判「环上相邻差为 1」不够，必须同时确认方向——升序环和降序环的代价公式不同，方向搞反答案会偏 1
- 代价公式里的「+2」是翻转两次（翻转 → 左旋 → 再翻转），漏掉第二次翻转就会少算一步
- `base_pos` 在降序分支要换成 `n-1` 的下标；`0` 的下标 `p` 与 `n-1` 的下标关系是 `(p+1) % n`，方向别记反
- `n == 1` 必须单独返回 0，否则 `nums[1]` 越界

## 总结

「两种保环操作 → 只可能是升序/降序环的旋转」是这类题的全部结论，剩下的只是算相位。判形时用 **相邻差乘积** 比手写两遍上升/下降逻辑更省事，但要记住断点必须显式跳过。
