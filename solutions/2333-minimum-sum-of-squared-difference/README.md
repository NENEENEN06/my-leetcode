# 2333. Minimum Sum of Squared Difference
- Difficulty: Medium
- Topics: Array, Math, Sorting, Heap (Priority Queue), Binary Search
- Language: C++
- 题目链接: https://leetcode.cn/problems/minimum-sum-of-squared-difference/

## 题目
给定两个正整数数组 `nums1`、`nums2` 和两个操作次数 `k1`、`k2`。每次操作可以把 `nums1` 或 `nums2` 中**恰好一个**元素加 1 或减 1，分别最多用 `k1`、`k2` 次。求操作后 $\sum (nums1_i - nums2_i)^2$ 的最小值。

关键化简：设 $d_i = |nums1_i - nums2_i|$。对 `nums1` 加 1 和对 `nums2` 减 1 对 $d_i$ 的效果完全一样（都让 $d_i$ 减 1），所以两个操作次数可以**合并成** $k = k_1 + k_2$，问题变成：

> 给一个非负数组 $d$，最多做 $k$ 次「把某个元素减 1」（不能减到负数），使 $\sum d_i^2$ 最小。

## 我的思路
要让平方和最小，就要**削掉最大的差**——平方函数是凸的，把高度不齐的柱子削平，比削矮柱子更划算（1 次操作削高峰能省下 $2d-1$，削矮峰只省很少）。

于是问题变成「把 $d$ 排序后从最高处开始削平，能削到哪一层」，用一个**前缀和**定位这一层，而不是逐单位模拟 $k$ 次：

1. `d` 降序排序，末尾补一个哨兵 `0`（方便处理「全部都能削成 0」）。
2. 从左往右累加前缀和 `cnt`，检查「把前 `pos+1` 个元素全部削到 `nums[pos+1]` 这一层」需要多少代价：`cnt - nums[pos+1]*(pos+1)`。代价 ≤ k 就说明能削得更低，`pos++` 继续；一旦代价 > k 就停在这层。
3. 停下后，先把前 `pos+1` 个元素削到 `nums[pos]` 高度（这一步的代价确定能从 k 里扣掉），剩下的 `k` 再在**这 `pos+1` 个元素之间平均分配**：每个先降 `k/(pos+1)`，余数 `k%(pos+1)` 个元素再各降 1（除法保证不会降到比下一层还低）。
4. 扫一遍算平方和；若 `pos == n` 说明所有差都能归零，直接返回 0。

## 代码

```cpp
class Solution {
public:
    long long minSumSquareDiff(vector<int>& nums1, vector<int>& nums2, int k1, int k2) {
        long long res=0;
        int n=nums1.size();
        vector<long long>nums(n);
        for(int i=0;i<n;i++){
            nums[i]=abs(nums1[i]-nums2[i]);
        }
        long long k=k1+k2;
        sort(nums.begin(),nums.end(),greater<long long>());
        nums.push_back(0);
        long long cnt=0;
        int pos=0;
        while(pos<n){
            cnt+=nums[pos];
            if(cnt-nums[pos+1]*(pos+1)>k){
                k-=cnt-nums[pos]*(pos+1);
                break;
            }
            pos++;
        }
        if(pos==n){
            return 0;
        }
        for(int i=0;i<n;i++){
            if(i<=pos){
                nums[i]=nums[pos]-k/(pos+1);
                if(i<k%(pos+1)){
                    nums[i]--;
                }
            }
            res+=nums[i]*nums[i];
        }
        return res;
    }
};
```

## 代码分析
- **正确性：经三重验证全部通过**（见文末「验证方法」）——小规模与**穷举出来的真实最优**一致（4000 组），中/大规模与堆模拟、按层统计两种独立写法一致（含 n=10⁵、k=10⁹ 的极限用例），官方三例全对（579 / 43 / 0）。
- **哨兵 `nums.push_back(0)` 是这版最巧妙的一笔**：它让「全部削成 0」这种情况自然落到 `pos == n` 分支，不需要在循环里单独判边界。同时它也保证 `nums[pos+1]` 永远可读，不会越界。
- **前缀和代替逐单位模拟**：`k` 可以到 2×10⁹，逐次削一个单位必然超时；这里用 `cnt - nums[pos+1]*(pos+1)` 一次算出「整层削平」的代价，只有整数运算，O(n log n) 全靠排序。
- **余数分配写法标准**：`k/(pos+1)` 是平均降幅（整数除法天然向下取整，保证不会越过 `nums[pos+1]`），`i < k%(pos+1)` 让余数落到前几个元素上，避免全压在同一个元素上。
- **可以更好的地方（都不影响正确性）**：
  - 变量名 `cnt`、`pos` 语义偏弱，`cnt` 其实是「前 pos+1 个元素之和」，`pos` 是「削平的层下标」，改成 `prefixSum`、`level` 更好读；
  - 复用 `nums` 数组原地改写（原始差 → 最终值），读代码时容易搞混「此刻的 nums 是差还是结果」，拆两个数组或加注释更稳；
  - `abs(nums1[i]-nums2[i])` 依赖 `nums1/nums2` 的元素在 int 范围内（本题满足），若数据范围变大，两个 int 相减要先转 `long long`。

## 复杂度
- 时间：O(n log n)（排序主导），后续扫描均摊 O(n)。
- 空间：O(n) 存差值数组；哨兵只占一个元素。极限用例（n = 10⁵、k = 10⁹）实测 **3.4 ms**。

## 易错点
- **前缀和必须用 64 位**：n 和 d 都到 10⁵ 时，前缀和最大 10¹⁰，`int` 直接溢出（本题官方数据就会触发）。
- **`k1 + k2` 用 int 相加刚好安全**：`2×10⁹ < 2147483647`（`INT_MAX` ≈ 2.147×10⁹），能过；但这是「刚好」，一旦题目把 k 放大就会溢出——写成 `(long long)k1 + k2` 更稳妥。
- **不要逐单位模拟**：k 最大 2×10⁹，每次找一个最大值来削，必然超时；要么排序 + 前缀和定位层（本解），要么按层统计。
- **余数要分散到不同元素**：`k/(pos+1)` 个给所有人，剩下 `k%(pos+1)` 个**一人一个**地再减 1，不能都堆在同一个元素上（堆在一起会让平方和更大）。
- **排序方向**：这里要削最大的差，必须**降序**排序；升序排就把最小的差削掉了，结果会偏大。
- **别忘了合并 k1、k2**：把两个操作数当独立约束分开处理会漏解——对 `d` 而言它们完全等价，合并后才是「总共能削多少」。
- **边界**：`n = 1`、`k = 0`、所有差都是 0、`k` 足够把所有差削平（返回 0）——这些都要能跑过，本版靠哨兵 + `pos==n` 分支覆盖。

## 验证方法
这题最容易出错的是「削平层的定位」和「余数分配」两处索引算术，所以用三套**互相独立**的参照交叉验证：

1. **穷举真实最优**（小规模 n≤3、k≤24）：枚举 `k` 个单位在每个差上的全部分配方案，取平方和最小者——这不是另一种贪心，是**答案本身的定义**，能直接证明最优性；4000 组零不一致。
2. **堆模拟**（k 较小的场合）：每次把当前最大的差减 1，重复 k 次；写法与本解完全不同（数据结构不同、不做层定位）；中规模 3000 组零不一致。
3. **按层统计**（大规模）：不排序、不做索引腾挪，用计数数组按「高度」自高向低整层压平，最后把剩余 k 平均分；n=10⁵、k=10⁹ 的 80 组极限用例零不一致。

三者都过，说明本解不只是「和另一个贪心一样」，而是**在穷举意义上确实取到了最优**。

## 总结
本题的核心是两步化简：**① 把两个操作次数合并成 k**（因为对差值而言效果等价）；**② 把「最小化平方和」转化成「把差值的柱子尽量削平」**（凸函数的最速下降方向永远是当前最高的那根）。

落地实现则是「排序 + 前缀和定位削平层 + 余数平均分配」，把 10⁹ 级别的操作次数压缩成 O(n log n) 的算术。这类「用算术一次性跨过大量相同操作」的思路值得记住：**只要每个单位的操作效果相同，就先想办法把整段操作合并成一次计算**。

## 复盘
- 容易想错的地方：① 把 `k1`、`k2` 当成对两个数组各自的独立限制（其实对差值完全等价）；② 试图逐单位模拟；③ 前缀和用 `int` 溢出；④ 余数分配全堆到一个元素上。
- 关键突破点：看出「削最陡的那根」= 把排序后的高柱子整层压平，于是可以用前缀和一次算出「压到下一层要多少代价」，从而定位能压到哪一层。
- 下次看到什么特征应该想到这个算法：题目要求「给定总操作次数，最小化某个凸函数（如平方和）」且每次操作对某个量的影响是 ±1 时，优先想「排序 + 前缀和/二分定位削平层」；若操作不改变相对顺序，也可用计数数组按层处理。
