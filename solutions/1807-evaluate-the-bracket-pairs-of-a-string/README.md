# 1807. Evaluate the Bracket Pairs of a String
- Difficulty: Medium
- Topics: Array, Hash Table, String
- Language: C++
- 题目链接: https://leetcode.cn/problems/evaluate-the-bracket-pairs-of-a-string/

## 题目
给定字符串 `s`（其中每个 `(...)` 都是一个键）和键值对列表 `knowledge`，把 `s` 里所有 `(key)` 替换成对应的值；键在 `knowledge` 里不存在时替换成 `?`，其余字符原样保留。

## 我的思路
先把键值对灌进哈希表，然后对 `s` 做一次线性扫描：遇到 `(` 就一路读到 `)` 收集出键，查表得值或 `?`；不是括号内的字符直接照抄。

- 建表：`mp[row[0]] = row[1]`，`unordered_map` 让每次查询平均 O(格式的键长)。
- 扫描：外层 `i` 走遍字符串；见 `(` 就把 `i` 前移一位，内层循环 `for(; s[i] != ')'; i++)` 逐字符拼出键名 `tmp`。
- 查表：`mp.find(tmp)` 命中就把值追加到结果，未命中追加 `'?'`。
- 内层循环结束时 `i` 正停在 `)` 上，外层 `for` 的 `i++` 恰好跳过它，所以括号不会被写进结果。

为什么正确：题目保证括号不嵌套、键非空且不含 `)`，因此「从 `(` 之后读到第一个 `)`」就是完整的键名，不会有歧义；其余字符按位复制即可保持顺序。

## 代码
```cpp
class Solution {
public:
    string evaluate(string s, vector<vector<string>>& knowledge) {
            unordered_map<string,string>mp;
            string res;
            for(auto &row : knowledge){
                mp[row[0]]=row[1];
            }
            int len=s.size();
            for(int i=0;i<len;i++){
                if(s[i]=='('){
                    i++;
                    string tmp;
                    for(;s[i]!=')';i++){
                        tmp+=s[i];
                    }
                    auto it=mp.find(tmp);
                    if(it!=mp.end()){
                        res+=it->second;
                    }
                    else{
                        res+='?';
                    }
                }
                else{
                    res+=s[i];
                }
            }
            return res;
    }
};
```

## 代码分析
- 正确性：正确。用 `std::regex` 做了完全不同的解析（正则一次性抓出所有 `(key)`）作为参照，随机 30000 组（含未知键、连续括号、含 `?` 的原文、键值含特殊字符）结果零不一致；题目示例 `"(name)is(age)yearsold"` + `[["name","bob"],["age","two"]]` 得到 `"bobistwoyearsold"` 也吻合。
- 关键实现：内层循环把 `i` 推到 `)` 上、由外层自增越过它，这个「指针交接」是本题最容易写错的地方；用 `unordered_map` 建表把每次查询降到平均 O(1)。
- 潜在 Bug：无（在题目给定的规范输入下）。若输入不保证「括号成对」，`for(; s[i] != ')'; i++)` 会越界读，需自行加边界保护。
- 可以改进的地方：
  1. **用 `find` + `substr` 代替逐字符拼接**：`size_t r = s.find(')', i); string tmp = s.substr(i, r - i); i = r;` —— 少一次循环，语义更清楚，也避免 `tmp += c` 的多次扩容。
  2. `res.reserve(s.size())` 预留容量（结果长度通常与 `s` 同量级），减少重新分配。
  3. 代码整体缩进多了 4 个空格（多了一层无效缩进），格式化一下更好读。

## 复杂度
- 时间复杂度：O(k + L)。建表 O(k)（k 为键值对个数），扫描 O(L)（L 为 `s` 长度，每个字符只被处理一次；拼接键名是逐字符 O(1) 追加）。哈希查询平均 O(1)，最坏 O(键长)（哈希冲突）。
- 空间复杂度：O(k + L)。哈希表存全部键值对，结果串长度不超过 `s` 长度的一半量级（未知键被压成 1 个 `?`）。

## 易错点
- **括号指针交接**：内层循环结束时 `i` 停在 `)`，若忘记让外层自增跳过（或自己再 `i++` 造成跳过两个字符），结果里会多出 `)` 或者漏掉紧随其后的字符。
- **未知键忘记输出 `?`**：只把命中值追加、未命中直接跳过，会静默丢字符。
- **原文里本身有 `?`**：`?` 既是「未知键」的输出，也可能是 `s` 中的普通字符；只要 `?` 出现在括号外就照抄，别把它当成特殊标记处理。
- **用 `map` 而非 `unordered_map`**：本题键值查询频繁，`map` 的 O(log k) 虽能过，但没有必要。
- **键名可能含数字/大小写**：直接用 `string` 比较即可，别做额外的规范化（比如转小写），会改变语义。
- **就地修改 `s`**：本题不需要，保持入参只读更安全。

## 总结
「带占位符的字符串替换」的通用套路是**建哈希表 + 单次扫描，遇到左定界符就取出键、查表、未命中给默认值**。本题的细节点在于「用内层循环定位右括号」时的指针交接：内层把下标推到定界符上，由外层自增越过，这是手写解析里最常见的一类越界/漏字符 bug。工程上更推荐 `find` + `substr` 一步到位。

## 复盘
- 容易想错的地方：把 `?` 当成「特殊符号」去判断原文是否已经包含；其实它只是未命中键的默认输出，原文中的 `?` 一律照抄。
- 关键突破点：意识到括号不嵌套、键不含 `)`，于是「读到第一个 `)`」就是完整键名，一整趟扫描即可，不需要栈或递归。
- 下次看到什么特征应该想到这个算法：需要把「定界符包裹的片段」映射成别的内容时，先看约束能否保证不嵌套——不嵌套就一趟扫描 + 哈希表，嵌套了才需要栈。
