# 1385. Find the Distance Value Between Two Arrays

- Difficulty: Easy
- Topics: Array, Two Pointers, Binary Search, Sorting
- Language: C++
- 题目链接: https://leetcode.cn/problems/find-the-distance-value-between-two-arrays/

## 题目

给定整数数组 `arr1`、`arr2` 和整数 `d`，返回两个数组的「距离值」。距离值定义为：`arr1` 中满足「对任意 `arr2[j]` 都有 `|arr1[i] - arr2[j]| > d`」的元素个数。

数据规模很小：两个数组长度都不超过 500，元素在 `[-1000, 1000]`，`0 <= d <= 100`。

## 我的思路

- 核心思想：对 `arr1` 的每个元素，去 `arr2` 里搜有没有「离它足够近」的元素；一个都找不到就让它计数。
- 使用的数据结构：无，直接在两个数组上双重循环。
- 算法流程：
  1. 外层扫 `arr1`，进来先把 `res` 加一（默认这个元素合格）。
  2. 内层扫 `arr2`，一旦 `abs(num1 - num2) <= d`，说明这个 `arr1` 元素不合格，把刚才加的一分减回去，`break` 掉内层。
  3. 内层完整走完都没命中，就说明它真的合格，加的那一分留着。
- 为什么这样做：「合格」的判据是「不存在靠得太近的元素」，正好对应内层的一次全量查找；用 `break` 把「存在」的判定提前结束。
- 关键状态 / 变量：`res`（合格元素计数）。
- 为什么能够得到正确答案：每个 `arr1` 元素恰好贡献 0 分或 1 分，且两种情况的判据与题目定义逐字对应，累加即答案。

## 代码

```cpp
// 1385. Find the Distance Value Between Two Arrays
// 逐个检查 arr1 的每个元素，只要 arr2 里存在一个「与它距离不超过 d」的元素，这个元素就不算数。
class Solution {
public:
    int findTheDistanceValue(vector<int>& arr1, vector<int>& arr2, int d) {
        int res = 0;
        for (int& num1 : arr1) {
            res++;                      // 先默认这个元素计入答案
            for (int& num2 : arr2) {
                if (abs(num1 - num2) <= d) {
                    res--;              // 找到「太近」的元素，撤销计数
                    break;              // 一个就够，后续不必再查
                }
            }
        }
        return res;
    }
};
```

## 代码分析

- 正确性：正确。内层 `break` 只影响当前 `arr1` 元素的判定，外层计数不受影响。
- 关键实现：`res++` / `res--` 的「先加后减」写法，本质是「默认合格，命中反例再撤销」，与「默认不合格，全部不命中才加」等价。
- 潜在 Bug：无明显错误。`abs(num1 - num2)` 的差值最大 2000，远在 `int` 范围内，不会溢出。
- 可以改进的地方：官方提示给了 O(n log m) 的做法——把 `arr2` 排序后对每个 `arr1[i]` 二分找最接近的值，只需要比较左右两个候选。本题 `500 × 500 = 25 万` 次比较，实测远在时限内，所以现在这样也合理；真要在 `n = m = 2 × 10^5` 的加强版上过，才需要换二分或双指针。

## 复杂度

- 时间复杂度：O(n·m)，最坏情况内层完整扫完 `arr2`。
- 空间复杂度：O(1)，只用了一个计数变量。

## 易错点

- `<= d` 而不是 `< d`：距离恰好等于 `d` 时元素也**不**合格（题目用的是「不大于」）。
- `break` 不能漏，否则同一元素会被重复 `res--`，答案偏小。
- `d = 0` 也合法，此时只有「相等」才算命中，别把 `d` 当正数默认处理。
- 用 `arr2` 做内层、`arr1` 做外层的方向别反：计数的对象是 `arr1` 的元素。

## 总结

判据是「不存在距离 ≤ d 的元素」，属于典型的「双重循环 + 提前退出」：外层遍历待计数的一方，内层找一个反例，找到就撤销。规模小时就是最优解；规模大时才值得先排序再二分。

## 复盘

- 我哪里容易想错：`res++` 放在循环开头、命中再减，一开始容易漏掉 `break` 导致减多次。
- 关键突破点：把「合格」翻译成「找不到反例」，才能直接用 `break` 短路。
- 下次看到什么特征应该想到这个算法：看到「对每个元素判断是否存在某个配对」且数据规模 ≤ 10^3，直接双重循环；规模上到 10^5 就要想到排序 + 二分，或者双指针扫描。
