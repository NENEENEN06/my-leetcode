# 2914. Minimum Number of Changes to Make Binary String Beautiful

- Difficulty: Medium
- Topics: String
- Language: C++
- 题目链接: https://leetcode.com/problems/minimum-number-of-changes-to-make-binary-string-beautiful/

## 题目

给定长度为偶数的 `01` 字符串 `s`，「美丽」的定义是：把它切成若干个长度为偶数的连续子串后，每一段都是「前半全 0、后半全 1」或「前半全 1、后半全 0」。求最少改多少个字符能让它变美丽。

## 我的思路

- **核心思想**：贪心 + 两两成组。因为每段长度是偶数，可以按 `(0,1)`、`(2,3)`、`(4,5)`… 每两个字符切一组；一组里两个字符相同就一定合法，不同就必须改掉其中一个。
- **为什么这样最省**：一个字符最多只能消除一处冲突，而每组内部的冲突互不影响，所以「每组单独处理」已经是下界，不存在跨组优化能更省。
- **实现**：从下标 1 开始每次 `i += 2`，比较 `s[i]` 和 `s[i-1]`，不同就 `result++`。

## 代码

```cpp
class Solution {
public:
    int minChanges(string s) {
        int result = 0;
        // 每两个字符一组，组内不一致就要改一次
        for (int i = 1; i < s.size(); i += 2) {
            if (s[i] != s[i - 1]) {
                result++;
            }
        }
        return result;
    }
};
```

## 代码分析

- 正确性：力扣站内已 AC（本机未复跑，代码取自该次 Accepted 提交）。
- 关键实现：`i += 2` 保证每次只看一组，`s[i - 1]` 就是这一组的左字符。
- 潜在 Bug：无。`i` 从 1 开始且步长 2，边界天然对齐偶数长度，不会越界。
- 可以改进的地方：没有实质优化空间——这已经是最优复杂度，任何写法都至少要把字符串扫一遍。

## 复杂度

- 时间复杂度：`O(n)`，扫一遍偶数下标。
- 空间复杂度：`O(1)`，只用了一个计数器。

## 易错点

- 别去真的「切段」：题目允许任意切分，切分方式本身不影响答案，只看相邻两字符是否配对。
- 下标起点是 1 而不是 0，步长是 2——写成 `i++` 会把同一对字符比较两次。
- 题目保证 `s` 长度为偶数，所以不用担心落单。

## 总结

- 这类「让序列满足某种成对性质」的题，先想清楚**最小冲突单元**是什么。这里就是相邻两个字符。
- 贪心能成立的关键是「冲突之间彼此独立」，一旦能证明这一点，逐个处理就是最优。
