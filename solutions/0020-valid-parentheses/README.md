# 20. Valid Parentheses
- Difficulty: Easy
- Topics: String, Stack
- Language: C++
- 题目链接: https://leetcode.cn/problems/valid-parentheses/

## 题目
给定只含 `()[]{}` 的字符串 `s`，判断括号是否**有效**：同类型括号必须正确配对，且顺序不能交叉错位，空串算有效。

## 我的思路
经典栈匹配：遇到左括号入栈，遇到右括号就看栈顶是不是它对应的左括号。

- 用 `map<char,char>` 存「右括号 → 左括号」的对应关系（`')'→'('`、`'}'→'{'`、`']'→'['`）。因为表里只有右括号，所以 `mp.find(ch)==mp.end()` 恰好可以直接判断「当前字符是左括号」。
- 左括号：`st.push(ch)`。
- 右括号：若栈空（没有可配对的左括号）或栈顶不是对应左括号 → 直接 `return false`；否则 `st.pop()` 消掉这一对。
- 扫完后返回 `st.empty()` —— 栈里还有左括号说明有没闭合的，同样无效。

关键点：`st.empty() || st.top()!=mp[ch]` 里 `empty()` 必须写在前面，靠短路求值避免对空栈调用 `top()`（未定义行为）。

## 代码
```cpp
class Solution {
public:
    bool isValid(string s) {
        stack<char>st;
        map<char,char>mp={
            {')','('},
            {'}','{'},
            {']','['}
        };
        for(auto ch:s){
            if(mp.find(ch)==mp.end()){
                st.push(ch);
            }
            else{
                if(st.empty()||st.top()!=mp[ch]){
                    return false;
                }
                else{
                    st.pop();
                }
            }
        }
        return st.empty();
    }
};
```

## 代码分析
- 正确性：正确。随机对拍（20 万组随机括号串，含空串、错配、交叉嵌套）与「反复删除相邻配对 `()`/`[]`/`{}` 直到不变」的独立判定法**零不一致**；另测 1.6 万组混入杂字符的串，本解法一律返回 false（与参照一致）。经典用例 `"()[]{}"`、`"([)]"`、`"(]"`、`"([{}])"` 全部吻合。
- 关键实现：用「右括号映射表」把两种字符区分开，省掉一个 `isLeft` 判断；短路写法保证了栈空时不会误调 `top()`。
- 潜在 Bug：无。
- 可以改进的地方：
  1. **`map` 换成 `switch` 或 `unordered_map`**：只有 3 条映射，`std::map`（红黑树）在这里纯属过度设计；`switch(ch){case ')': ...}` 或 `unordered_map` 常数更小。
  2. **奇偶早退**：有效括号串长度必为偶数，开头加 `if(s.size()%2) return false;` 能省掉一半无解串的扫描。
  3. `for(auto ch : s)` 可写 `for(char ch : s)`；`mp[ch]` 在 `find` 已命中的分支里是安全的，但用 `mp.at(ch)` 或迭代器更严谨（避免误写成插入语义）。
  4. 也可以完全不建表：直接 `if(ch=='('||ch=='['||ch=='{') push; else { 用 switch 判断配对 }`，省掉哈希/树的查找开销。

## 另一种写法（同一题的第二个版本）

仓库里同时存了两份实现：`solution.cpp` 是上面这版（映射表，为主），`solution2.cpp` 是下面这版（不用映射表，直接用字符本身的性质判断）：

```cpp
class Solution {
public:
    bool isValid(string s) {
        stack<char>st;
        for(auto ch:s){
            if(string("([{").find(ch)!=string::npos){   // 原版写的是 contains（C++23 才有），改成 find 即可在 C++17 用
                st.push(ch);
            }
            else{
                if(st.empty()||(st.top()!=ch-2&&st.top()!=ch-1)){
                    return false;
                }
                st.pop();
            }
        }
        return st.empty();
    }
};
```

思路：栈里只可能压入三种左括号，而三个右括号与对应左括号的编码距离是固定的 ——

```
')'=41  '('=40   差 1
']'=93  '['=91   差 2
'}'=125 '{'=123  差 2
```

于是「栈顶是否是这个右括号的配对」可以写成 `top == ch-1 || top == ch-2`，`ch-2`/`ch-1` 中不成立的那个在 ASCII 上分别是 `'`(39)`、`'\'`(92)`、`'|'(124)`，都不可能出现在栈里，所以这种「取两个候选」的写法不会误判。实测：随机 20 万组与暴力删合法，且与上面的映射表版结果**完全一致**。

**两个坑**：

1. 原始写法用的 `string::contains` 是 **C++23** 才加入的接口，用 C++20 编译会直接报 `'std::string' has no member named 'contains'`（LeetCode 默认档常常仍是 C++20，需要手动切到 C++23）。记录在仓库里的这份已改成 `find(ch)!=string::npos`，C++17 即可编译。
2. `ch-2` / `ch-1` 属于「魔法数字」：它依赖 ASCII 编码相邻、且依赖「栈里只会出现三种左括号」这一前提。可读性和健壮性都不如 `switch`，除非追求极致短小，否则不推荐在工程代码里这么写。

## 复杂度
- 时间复杂度：O(n)。每个字符至多一次入栈或出栈，配对的查找是常数级（`map` 里只有 3 个元素，O(log 3) 视作 O(1)）。
- 空间复杂度：O(n)。最坏情况（全是左括号）栈深为 n，配套的 `map` 是常数空间。

## 易错点
- **栈空时先调 `top()`**：写成 `st.top()!=mp[ch] || st.empty()` 就是未定义行为，可能崩也可能给出随机结果；顺序必须是「先判空」。
- **只判配对、忘记最终清空**：不写 `return st.empty()` 而写 `return true`，会让 `"(("`、`"((()"` 这类「多出左括号」的串误判为有效。
- **错配类型没查**：只判断「栈非空就 pop」，会把 `"([)]"` 判成 true（正确结果应是 false，因为交叉嵌套）。
- **把右括号写成入栈**：搞混方向会让逻辑整体反过来。
- **字符串含其它字符**：本题只给三类括号。实测若混入杂字符（如 `a`、`1`），它们会被当作左括号压栈且永远弹不出去（映射表里没有能配对它们的右括号），最终返回 false —— 对本题输入范围没有影响；但若题目放宽输入，就得先加白名单判断，否则「非括号字符」的语义会与预期不符。
- **空串**：`s=""` 时循环不执行、`st.empty()` 为 true，返回 true，符合题目定义（空串有效）。

## 总结
「括号匹配」是栈的第一个经典应用，判定三要素：**遇左入栈、遇右比对栈顶、扫完栈必须为空**。用「右括号→左括号」的映射表来区分左右可以少写一个判断，但要注意栈空必须先判，以及「类型必须成对」这一条不能省。同族问题（最长有效括号、括号嵌套深度、括号字符串拆分）都建立在这套栈匹配的直觉上。

## 复盘
- 容易想错的地方：以为只要「左右括号数量相等」就有效（`"([)]"` 会打脸），或者忘记最后检查栈是否为空（`"(("` 会打脸）。
- 关键突破点：把「正确的配对」转化为「每个右括号必须匹配**最近一个尚未闭合的同类型**左括号」，而这正是栈顶的定义。
- 下次看到什么特征应该想到这个算法：字符串里出现具有「后进先出」配对关系（括号、标签、表达式求值、逆波兰式）时，先想栈；凡是要求「就近匹配」的结构，栈几乎总是对的工具。
