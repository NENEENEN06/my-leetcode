# 3693. Climbing Stairs II

- Difficulty: Medium
- Topics: Dynamic Programming
- Language: C++
- 题目链接: https://leetcode.cn/problems/climbing-stairs-ii/

## 题目

楼梯有编号 `0` 到 `n` 共 `n + 1` 级台阶，给定**下标从 1 开始**的数组 `costs`（长度 `n`），`costs[i]` 是踩上第 `i` 级台阶的成本。从第 `i` 级只能跳到 `i + 1`、`i + 2`、`i + 3`，跳一次的成本是 `costs[j] + (j - i)²`。从第 `0` 级出发，求到达第 `n` 级的最小总成本。

## 我的思路

- 核心思想：最短路的一维 DP。每次跨的级数只有 1、2、3 三种，而多跨一级要多付 `(j - i)²`，所以走到第 `i` 级的最优解只可能来自 `i-1`、`i-2`、`i-3` 这三个前驱，取三者中「前驱最优成本 + 跨过去多花的平方代价」的最小值。
- 使用的数据结构：一维数组 `dp`，`dp[i]` 表示到达第 `i` 级台阶的最小总成本；从起点出发，故 `dp[0] = 0`。
- 算法流程：
  1. `n == 1` 直接返回 `costs[0] + 1`（只有一步，落地成本 + `1²`）。
  2. `n == 2` 直接返回 `min(costs[1] + 4, costs[0] + costs[1] + 2)`（一步直跳，或经 1 级中转；数组 0-indexed，`costs[1]` 就是第 2 级）。
  3. 初始化 `dp[1] = costs[0] + 1`、`dp[2] = costs[1] + min(dp[1] + 1, dp[0] + 4)`。
  4. 从 `i = 3` 递推到 `n`：`dp[i] = costs[i-1] + min(dp[i-1] + 1, dp[i-2] + 4, dp[i-3] + 9)`。
- 为什么这样做：跳跃代价 `(j - i)²` 与从哪来无关，只与跨了几级有关（1 / 4 / 9），所以子问题之间没有耦合，可以直接按距离从小到大递推；每一级都把「最后一步跨几级」的三种可能枚举完，不会漏掉最优解。
- 关键状态 / 变量：`dp[i]` 是「走到第 `i` 级的最小总成本」；`costs[i-1]` 是踩上第 `i` 级的固定成本（数组 0-indexed 与台阶 1-indexed 之间的错位是本题最关键的一处转换）。
- 为什么能够得到正确答案：设最优路径最后一步从 `i-d` 跳到 `i`（`d ∈ {1,2,3}`），那么 `i-d` 之前那段必然也是走到 `i-d` 的最优路径——否则换掉它能得到更便宜的整条路径。于是 `dp` 的递推正好覆盖了所有最优路径的形态。

## 代码

```cpp
// 3693. Climbing Stairs II
// dp[i] = 走到第 i 级台阶的最小总成本；每步只能跨 1/2/3 级，
// 跨 d 级要多付 d^2 的平方代价，所以 dp[i] 只需要看前面三级。
class Solution {
public:
    int climbStairs(int n, vector<int>& costs) {
        // n = 1 / n = 2 时不构成完整的三级前驱，单独返回，也省掉下标越界
        if (n == 1) {
            return costs[0] + 1;
        }
        if (n == 2) {
            return min(costs[1] + 4, costs[0] + costs[1] + 2);
        }
        vector<int> dp(n + 1, 0);  // dp[0] = 0：起点本身不花钱
        dp[1] = costs[0] + 1;      // 0 -> 1：落地成本 + 1^2
        dp[2] = costs[1] + min(dp[1] + 1, dp[0] + 4);  // 直跳 0 -> 2，或经 1 中转
        for (int i = 3; i <= n; i++) {
            // 三种来路各试一次：+1 是一级跳的平方代价，+4 两级，+9 三级
            dp[i] = costs[i - 1] + min(dp[i - 1] + 1, min(dp[i - 2] + 4, dp[i - 3] + 9));
        }
        return dp[n];
    }
};
```

## 代码分析

- 正确性：正确。本机与暴力解对拍（枚举所有 1/2/3 跳跃序列取最优）`n = 1..12` 各 500 组随机数据，共 6000 组零差异；官方三个样例（13 / 11 / 12）也都能复现。
- 关键实现：`costs` 是 1-indexed 而 C++ 数组 0-indexed，所有 `costs[i]` 都写成 `costs[i-1]`；递推里 `dp[0] = 0` 让 `i = 3` 那一步天然包含「从起点直跳三级」的情况（`dp[0] + 9`），不需要额外特判。
- 潜在 Bug：`n == 2` 里的 `costs[0] + costs[1] + 2` 是两个 `+1` 合成的，若之后改成「跨 1 级只收 1 次落地成本」之类的变体，这里会漏改。`int` 也刚好够用：最坏情况全走一步是 `∑costs + n ≤ 1e5 × 1e4 + 1e5 ≈ 1.0e9`，离 `INT_MAX`（2.1e9）还有一倍余量，但如果上界提到 `n = 1e6` 就必须换 `long long`。
- 可以改进的地方：只需要前三级的结果，`dp` 数组可以压成三个变量滚动，空间从 `O(n)` 降到 `O(1)`；本题 `n ≤ 1e5`，`400 KB` 的数组实测 `1.2 ms` 就够用，压不压差别不大。真要压，注意保留 `dp[0]` 那一项，别让 `i = 3` 的特例冒出来。

## 复杂度

- 时间复杂度：O(n)，从 3 到 n 扫一遍，每次常数次比较。
- 空间复杂度：O(n)，一个长度 `n + 1` 的 `dp` 数组；可优化到 O(1)。

## 易错点

- **1-indexed 的 `costs`**：`costs[i]` 是第 `i` 级台阶的成本，代码里必须写 `costs[i-1]`。写成 `costs[i]` 会整体错位一格，样例能过、随机数据必挂。
- **边界 `n = 1` / `n = 2`**：此时凑不齐三个前驱，从 `i = 3` 开始递推会读越界的 `dp[-1]`，所以必须先特判返回。
- **`i = 3` 的来源**：`dp[0]` 必须显式初始化为 0，否则「起点直跳三级」这条路径（代价 `costs[2] + 9`）会被漏掉。
- **平方代价不是固定值**：跨 1 / 2 / 3 级分别是 `1 / 4 / 9`，不是线性的 1 / 2 / 3；写成 `dp[i-d] + d` 就退化成普通爬楼梯了。
- **`n == 2` 的两种走法**：一步到 2（`costs[1] + 4`）和分两步（`costs[0] + 1 + costs[1] + 1`），漏掉任一种都可能给出次优解。

## 总结

跳跃范围只有 `1..3` 的最短路 DP，是所有「带权爬楼梯」问题的标准形态：把「最后一步跨几级」枚举完，子问题就切干净了。真正要盯的是三件事——`costs` 的 1-indexed 偏移、`dp[0] = 0` 这个隐含起点、以及平方代价 `d²` 别写成 `d`。

## 复盘

- 我哪里容易想错：一开始容易把 `costs` 直接按 `costs[i]` 用（以为和台阶号对齐），或者从 `i = 1` 就开始递推、拿 `dp[-1]` 当前驱。
- 关键突破点：认出「跨 d 级多付 d²」等价于「边权只跟这一步跨了几级有关」，于是问题从二维（从哪来 + 到哪去）退化成一维的三前驱递推。
- 下次看到什么特征应该想到这个算法：每次只能前进固定的 1..k 步，且每步的额外代价只与步长有关（平方、常数、递增序列）——都是一维三/多前驱 DP。
