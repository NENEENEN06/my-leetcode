# 22. Generate Parentheses
- Difficulty: Medium
- Topics: String, Dynamic Programming, Backtracking
- Language: C++
- 题目链接: https://leetcode.cn/problems/generate-parentheses/

## 题目
给定括号对数 `n`，生成所有由 `n` 对括号组成的**合法**括号串（返回顺序不限）。

## 我的思路
把「构造括号串」看成一棵状态树，用 BFS 逐层扩展：队列里每个状态是 `(当前串, 当前平衡数 l)`，`l` 定义为「已放的左括号数 − 已放的右括号数」。

- 初始状态：串为 `"("`、`l = 1`（第一个字符必须是左括号，否则不是合法前缀）。
- 每次从队首取出一个状态，长度已到 `2n` 且 `l == 0`（左右数量相等、不欠不余）就是一个合法解，收进答案。
- 未到 `2n` 时尝试两种扩展：
  - 追加 `)`：要求 `l > 0`（前面有未闭合的左括号才能闭合，保证前缀不出现「右多于左」）；扩展后 `l - 1`。
  - 追加 `(`：要求 `l < n`（左括号总数不能超过 n）；扩展后 `l + 1`。
- 队列空了就结束，`res` 里是所有合法串。

为什么覆盖全部且不重复：每个合法串都对应从根出发、每步合法的一条路径，BFS 会把它完整走通；而串的字符序列唯一决定了这条路径（每一步追加什么字符就是路径标签），所以同一串只会被测到一次，不会重复入答案。

正确性还可以从 `l` 的意义直接看出来：`l` 就是括号串的「当前深度」，`l ≥ 0` 保证任意前缀不出现右括号多于左括号，终态 `l = 0` 保证左右数目相等、串闭合。

## 代码
```cpp
class Solution {
public:
    vector<string> generateParenthesis(int n) {
        vector<string>res;
        queue<pair<string,int>>q;
        q.push({"(",1});
        while(!q.empty()){
            auto [st,l]=q.front();
            q.pop();
            int len=st.size();
            if(len==2*n&&l==0){
                res.push_back(st);
            }
            if(len<2*n){
                if(l<=n&&l>0){
                    q.push({st+')',l-1});
                }
                if(l<n&&l>=0){
                    q.push({st+'(',l+1});
                }
            }
        }
        return res;
    }
};
```

## 代码分析
- 正确性：正确。对 `n = 1..10` 逐一与「DFS 回溯 + 剪枝」的独立实现比较**集合是否完全相同**（排序后逐元素比对），同时校验结果里每个串都合法、个数等于卡特兰数 C(2n,n)/(n+1)，全部吻合。
- 关键实现：
  1. 用 `l` 把「合法性」压缩成单个整数，不用额外栈或计数数组；
  2. 两个分支的守卫条件 `l>0`（可闭合）与 `l<n`（可开启）正好对应两种可能的越界；
  3. 只在 `len==2n && l==0` 时收集答案，长度不足时不可能提前收。
- 潜在 Bug：无。
- 可以改进的地方：
  1. **守卫条件里的 `l<=n` 与 `l>=0` 是冗余的**：`l>0` 时必然 `l<=n`（`l` 最多到 n），`l<n` 时必然 `l>=0`；删掉后条件更干净。
  2. **BFS 比 DFS 占内存**：BFS 队列会同时持有同一层的所有部分串（指数级），而回溯只需一条路径的递归栈 O(n)。n 大时（本题 n ≤ 8，无所谓）差异明显；想要更省内存可改成递归回溯。
  3. 结果顺序由 BFS 决定（按长度分层，同层按入队顺序），题目不要求字典序，但若想要字典序输出需要用 DFS 并优先扩展 `(`。
  4. 也可以用「卡特兰数 DP」写法：`dp[i] = "(" + dp[j] + ")" + dp[i-1-j]`，思路不同但结果相同。

## 复杂度
- 时间复杂度：O(n · Catalan(n))。生成第 k 个合法串要 O(n) 字符操作，合法串个数是第 n 个卡特兰数（n=8 时为 1430）。
- 空间复杂度：O(n · Catalan(n))。BFS 队列在最坏情况下持有大量部分串；递归回溯版可降到 O(n)（不含答案本身）。

## 易错点
- **忘了「第一个字符必须是 `(`」**：若把空串 `""、l=0` 作为初始状态，会生成大量非法串（开头就是 `)`）；本解法直接以 `"("` 起步规避。
- **只判 `len == 2n` 就收答案**：必须同时 `l == 0`，否则会把 `"(()"` 这种没有闭合的串当成解。
- **两个守卫条件写反**：`)` 用 `l>0`、`(` 用 `l<n`，反了会生成非法串或漏解（`l` 变成负数或超过 n）。
- **`l` 的定义不统一**：本解法 `l` 是「净深度 = 左 − 右」；如果同时维护「已用左括号数」和「深度」两个变量，容易更新不一致。
- **重复收集**：若把状态写成只有串而没有 `l`，或在 BFS 里对同一串多次入队，就会产生重复答案（本解法每个串的路径唯一，天然无重复）。
- **n=0 的边界**：题目约束 `1 ≤ n ≤ 8`；若 n=0，正确输出是 `[""]`，而本解法从 `"("` 起步会返回空数组——超出题目范围，知道即可。

## 总结
「生成所有合法括号串」的标准框架是**合法性压缩 + 状态搜索**：用一个量 `l`（净深度）刻画当前串的合法状态，只要 `0 ≤ l ≤ n` 就还能继续扩展，终态要求 `l = 0`、长度 `2n`。BFS 和 DFS 都能做，区别只在内存（DFS 更省）和输出顺序（DFS 天然字典序）。同族问题（判断有效括号、最长有效括号、拆分括号串）共享同一套「前缀深度约束」的判据。

## 复盘
- 容易想错的地方：想先枚举全部 2^(2n) 个串再筛合法性（指数爆炸）；或者只按「左右数量相等」判断合法（漏掉前缀条件）。
- 关键突破点：把「任意前缀右括号不多于左括号」这一约束识别为「净深度 l ≥ 0 且 ≤ n」，于是搜索空间从 2^(2n) 降到卡特兰数级别，而且剪枝条件就写在转移里。
- 下次看到什么特征应该想到这个算法：要求「生成所有满足某种前缀约束的序列」——把约束写成每一步的可行区间（这里是 `0 ≤ l ≤ n`），然后 BFS/DFS 按区间扩展，天然只遍历合法前缀。
