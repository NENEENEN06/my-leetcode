# 3863. Minimum Operations to Sort a String
- Difficulty: Medium
- Topics: String
- Language: C++
- 题目链接: https://leetcode.cn/problems/minimum-operations-to-sort-a-string/

## 题目
给定小写字母字符串 s。每次操作可以选取一个**不是整个字符串**的子串，把它按非降序排序。求把整个串变成非降序所需的最少操作次数；做不到返回 -1。

## 我的思路
答案只可能是 0 / 1 / 2 / 3 / -1，逐个判掉即可：

- **0**：本来就非降序。
- **-1**：n == 2 且逆序。此时唯一能选的子串长度是 1，排序等于没动，永远换不过来。n >= 3 时总能排好——可以反复排长度为 2 的子串，等价于冒泡排序，而长度 2 < n 是合法操作。
- **1**：最小值在首位，排 `[1..n-1]` 即可；或最大值在末位，排 `[0..n-2]` 即可。
- **3**：最小值在最后一位、同时最大值在第一位，两头的"错位"要用掉三次操作（先把它俩挪出来，再把剩下的一段排序）。
- **2**：其余情况。

实现上只扫一遍：`flag` 记录是否已经有序，`min_pos` 记录最小值的位置（严格小于才更新，取最早出现的），`max_pos` 记录最大值的位置（反向遍历、严格大于才更新，取最晚出现的）。这样两个位置都取在"最靠近边界"的那一侧，后面三个判断可以直接比下标。

## 代码
```cpp
class Solution {
public:
    int minOperations(string s) {
        int n=s.size();
        if(n==2&&s[0]>s[1]){
            return -1;
        }
        bool flag=true;
        int min_pos=0;
        int max_pos=n-1;
        for(int i=1;i<n;i++){
            if(flag&&s[i]<s[i-1]){
                flag=false;;
            }
            min_pos=(s[i]<s[min_pos])?i:min_pos;
            max_pos=(s[n-1-i]>s[max_pos])?(n-1-i):max_pos;
        }
        if(flag){
            return 0;
        }
        if(min_pos==0||max_pos==n-1){
            return 1;
        }
        if(min_pos==n-1&&max_pos==0){
            return 3;
        }
        return 2;
    }
};
```

## 代码分析
- 正确性：正确
- 关键实现：一次遍历同时求出「是否已有序」「最小值位置」「最大值位置」，三个判断全部化成下标比较
- 潜在 Bug：无。`flag=false;;` 那个多余分号不影响语义
- 可以改进的地方：`min_pos` / `max_pos` 的更新可以合成一个循环体，已经是了；可读性上把 `-1 / 0 / 1 / 3 / 2` 的判定顺序按答案大小排一下会更直观

## 复杂度
- 时间复杂度：O(n)，只扫一遍
- 空间复杂度：O(1)，只用了几个下标和布尔变量

## 易错点
- **漏掉答案 3**：只想到 0/1/2 是这道题最常见的坑，`"cba"` 这类"最小在尾、最大在头"的串需要 3 次
- **n == 2 的判断**：长度为 2 时唯一合法子串长度是 1，排序无效，所以必须单独判 -1；n >= 3 则一定可行
- **最小值/最大值取哪个位置**：最小值要取**最早**出现的、最大值要取**最晚**出现的，否则 `"abca"` 这种重复字符会把 `min_pos==0` 判丢，答案从 1 变成 2
- **"非整个字符串"这个限制**：决定了最坏情况是 3 而不是更少，也决定了 n == 2 时无解

## 总结
这类题的关键不是模拟操作，而是把操作能力翻译成对字符位置的判断：能一次搞定的只有"一端已经到位"的情况，两端都错位就至少要三次。先把答案的取值范围想清楚（0/1/2/3/-1），再针对每个值找判据，比直接推演操作过程快得多。

## 复盘
- 容易想错的地方：以为 n == 2 也能靠交换修好，忽略了"子串不能是整个串"
- 关键突破点：意识到 n >= 3 时可以靠长度为 2 的子串做冒泡，所以无解只存在于 n == 2 且逆序
- 下次看到类似"每次排序一个子串"的题，先想"这个操作能不碰整个串吗"，答案往往只落在一个很小的集合里
