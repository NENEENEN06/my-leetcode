# 1190. Reverse Substrings Between Each Pair of Parentheses
- Difficulty: Medium
- Topics: String, Stack
- Language: C++
- 题目链接: https://leetcode.cn/problems/reverse-substrings-between-each-pair-of-parentheses/

## 题目
给定只含小写字母和括号的字符串 `s`，把每一对括号**内部**的子串反转，最后删掉所有括号，返回结果字符串。括号保证合法配对。

## 我的思路
不用「先展开再拼接」的正向模拟，而是用**栈记录左括号的下标 + 就地整段翻转**：

- 扫描一遍 `s`：遇到 `(` 就把它的下标压栈；遇到 `)` 就弹出栈顶下标 `l`（它与当前 `i` 配对），把 `s[l..i]`（**含两端括号**）整体翻转。
- 再扫一遍，把所有括号字符剔掉，剩下的就是答案。
- 因为 `s` 是**按值传递**的参数（`string s` 而非引用），就地翻转不会影响调用方的数据。

为什么正确：扫描到某个 `)` 时，栈顶必然是「最内层尚未闭合的左括号」——也就是它的匹配括号。于是第一层翻转先把最内层括号内的内容反转；之后处理外层时整段再翻一次，内层已经反转过的内容会被一起带回来，恰好等价于「由内向外逐层反转」。翻转是自逆运算（翻两次还原），这一性质保证了同一区段被反复翻时不会算错；最后统一删除括号即可。

举例：`(u(love)i)` —— 先遇到内层 `(love)` 翻转得 `(u(evol)i)`，再遇到外层翻转得 `)i(love(u`，删除括号后得到 `iloveu`。

## 代码
```cpp
class Solution {
public:
    string reverseParentheses(string s) {
        stack<int>st;
        string res;
        int len=s.size();
        for(int i=0;i<len;i++){
            if(s[i]=='('){
                st.push(i);
            }
            if(s[i]==')'){
                int l=st.top();
                int r=i;
                st.pop();
                reverse(s.begin()+l,s.begin()+r+1);
            }
        }
        for(int i=0;i<len;i++){
            if(s[i]!='('&&s[i]!=')'){
                res+=s[i];
            }
        }
        return res;
    }
};
```

## 代码分析
- 正确性：正确。随机对拍用**另一种算法**（栈里存字符串：遇 `(` 压入空串，遇 `)` 弹出并反转后接回上一层）作为参照，15000 组零不一致；三道经典用例 `(abcd)`→`dcba`、`(u(love)i)`→`iloveu`、`(ed(et(oc))el)`→`leetcode` 全部吻合。
- 关键实现：
  1. 栈里存的是**下标**而不是字符，所以配对的是一段区间；
  2. 翻转区间必须**含两端括号**（`begin()+l` 到 `begin()+r+1`，右端开区间），因为括号也会被一起搬动，这正是「最后统一删括号」能成立的前提；
  3. 一趟翻转 + 一趟过滤，第二次遍历复用同一份（已翻转过的）字符串。
- 潜在 Bug：无。题目保证括号合法，`st.top()` 不会在空栈上取。
- 可以改进的地方：
  1. **本解法最坏 O(n²)**（每对括号都翻转一次，n=2000 时约 4×10⁶ 字符搬移，能过但不算优）。经典 O(n) 做法是「跳跃法」：先扫一遍把所有括号配对关系存进数组，再让指针沿字符串走，遇到 `(` 就跳到它的配对括号处并翻转前进方向，直到走完；每个字符只访问一次。
  2. `res.reserve(s.size())` 预留容量；第二趟也可以原地压缩（`write` 指针）省一次拷贝。

## 复杂度
- 时间复杂度：O(n²) 最坏。每次翻转的代价是配对区间长度，最坏（如 `((((...))))`）总搬移量是 O(n²)；n ≤ 2000 时约 4×10⁶ 次操作，可通过。
- 空间复杂度：O(n)。栈最多存 n/2 个下标，结果串 O(n)。

## 易错点
- **翻转区间写成 `[l, r)`**：漏掉右括号，导致括号位置逐渐错乱，最终结果多字符或少字符。必须 `r+1`。
- **最后忘记删括号**：翻转只搬位置、不删字符，括号必须统一过滤掉。
- **以为括号也要保留**：题面明确要求删掉所有括号，别把 `(` `)` 写进结果。
- **用 `s[i]=='('` 与 `')'` 两个并列 `if`**：本题这样写没问题（一个字符不可能同时是两者），但若用 `if/else if` 思维去看会误以为有 bug；反过来也提醒自己别写成 `if(...) ... else if(...) ... else` 之外还会漏掉普通字符的处理——这里的普通字符不处理，是因为它们会被第二趟照抄。
- **原地改传入字符串**：本题参数是值传递，安全；如果写成 `string& s` 就会破坏调用方数据（同类题的常见事故）。
- **越界**：翻转时 `begin()+r+1` 在 `r == len-1`（右括号在末尾）时正好等于 `end()`，合法；写成 `+r+2` 就越界。

## 总结
「括号嵌套 + 反转」类问题的两种主力解法：① **栈存下标 + 整段翻转**（本解法，代码短、最坏 O(n²)）；② **先求配对关系再一遍跳跃扫描**（O(n)）。两者都依赖同一个性质——扫描到 `)` 时栈顶就是它的匹配括号，因此括号的配对关系可以在**一趟线性扫描**里确定。记住「翻转是自逆运算」，就能理解为什么反复整段翻不会算错。

## 复盘
- 容易想错的地方：第一反应是「用栈把字符串一段段拼起来再反转」（也就是我用来对拍的那种写法），逻辑直观但要多份临时字符串；另一种错法是反转区间只取括号内部（不含括号），结果括号边界会逐渐错位。
- 关键突破点：意识到括号也会被翻转搬运，而且最后要统一删除——于是可以在原串上就地翻，省掉所有拼接。
- 下次看到什么特征应该想到这个算法：字符串里出现**配对定界符**、又要对「层内内容」做可交换/自逆的操作（反转、取反、大小写翻转）时，优先考虑「栈存下标 + 就地操作」；如果数据量到 10⁵ 级别，再换成 O(n) 的跳跃法。
