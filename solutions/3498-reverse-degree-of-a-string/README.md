# 3498. Reverse Degree of a String
- Difficulty: Easy
- Topics: String, Simulation
- Language: C++
- 题目链接: https://leetcode.cn/problems/reverse-degree-of-a-string/

## 题目
小写字母的「反序位置」是它在字母表里倒着数的序号：`'a'` 记 26、`'b'` 记 25 …… `'z'` 记 1。字符串的「反序度」= 每个字符的反序位置乘以它的 1-based 下标，再全部相加。给定小写字符串 `s`，求它的反序度。

## 我的思路
一次线性扫描，边扫边累加，不需要额外存储。

- 下标 1-based，所以第 `i` 个字符（0-based）的权重就是 `i + 1`。
- 反序位置用字符码直接算：`'z' + 1 - s[i]`。`'z'` 是 122，加 1 得 123；`s[i]` 为 `'a'`(97) 时得到 26，为 `'z'`(122) 时得到 1，正好是倒序编号。
- 累加进 `ans`，最后返回。

关键变量只有 `ans`（累加器）和循环下标 `i`，没有状态需要维护。

## 代码
```cpp
class Solution {
public:
    int reverseDegree(string s) {
        int ans=0;
        int n=s.size();
        for(int i=0;i<n;i++){
            ans+=(i+1)*('z'+1-s[i]);
        }
        return ans;
    }
};
```

## 代码分析
- 正确性：正确。`'z'+1-s[i]` 与「26 − (s[i] − 'a')」完全等价（ASCII 里小写字母连续），1-based 权重也用 `i+1` 写对了。实测 `"abc"` → 148、`"z"` → 1，与题面一致。
- 关键实现：用字符码差直接算反序位置，省掉查表；一次遍历，无副作用。
- 潜在 Bug：无。题面 `1 ≤ s.length ≤ 1000`，最大情况全 `'a'`：`26 × (1+2+…+1000) = 26 × 500500 = 13 013 000`，远小于 `int` 上限 2.1×10⁹，不会溢出。
- 可以改进的地方：仅可读性 —— `'z'+1-s[i]` 这种「字符码算术」要读者在脑子里折算，写成 `26 - (s[i] - 'a')` 更直观（也避免了「字母必须连续」这一隐含假设，虽然 ASCII 成立）；`int n=s.size()` 会有 signed/unsigned 警告隐患，改成 `size_t` 或 `int(n)` 更严谨。

## 复杂度
- 时间复杂度：O(n)。每个字符一次减法、一次乘法、一次加法。
- 空间复杂度：O(1)。只用了常数个整型变量（`s` 是入参不计）。

## 易错点
- **权重用成 0-based**：乘 `i` 而不是 `i+1`，结果会整体偏小。
- **反序位置算反**：把 `'a'` 记成 1、`'z'` 记成 26 就变成「正序度」了，正好差一个 `27 × (1+…+n) ` 的偏移。
- **用 `'z' - s[i]`**：会得到 25…0，少了那个 `+1`，整体偏小 `1+2+…+n`。
- **溢出**：本题范围内 `int` 够用，但若题目把长度提到 10⁵ 量级，累加规模变成 26×5×10⁹，必须换 `long long` —— 知道临界点在哪比死记更稳。
- **忽略大小写**：题面保证全是小写字母，所以不需要 `tolower`；若输入混入大写，字符码算术会直接算错（不会报错，只会静默给出错误结果）。

## 总结
「字符的字母表序号 × 位置权重再求和」是字符串模拟题的常见形态，核心就三件事：序号怎么映射（这里倒序：`'z'+1-c`）、权重怎么取（1-based 用 `i+1`）、累加规模会不会溢出（`int` 还是 `long long`）。字符码算术能省掉查表，但要在注释里说明等价形式，别让读者自己折。

## 复盘
- 容易想错的地方：`'z'+1-c` 里的 `+1` 最容易漏（漏了就变成 25…0）。
- 关键突破点：认出「倒序编号 = 123 − 字符码」这条等价关系，一行替代查表数组。
- 下次看到什么特征应该想到这个算法：凡是「按字母表位置加权求和」的字符串题，一律 O(n) 一遍扫完；只有在需要多次随机访问且字母表很大时才考虑预处理。
