# 0940. Distinct Subsequences II

- Difficulty: Hard
- Topics: String, Dynamic Programming
- Language: C++
- 题目链接: https://leetcode.cn/problems/distinct-subsequences-ii/

## 题目

给定一个只含小写字母的字符串 `s`，统计 `s` 的所有**不同**的**非空子序列**的个数。子序列由删除若干字符（也可以一个不删）得到，剩余字符保持原有相对顺序。因为结果可能很大，需要对 `10^9 + 7` 取模。

## 我的思路

- 核心思想：线性动态规划 + 按"最近一次出现的相同字符"截断去重。`dp[i]` 表示把 `s[i]` 纳入考虑后，相比前缀 `s[0..i-1]` **新增**的不同子序列个数。每个位置的 `dp[i]` 归属互不重叠，所以答案 = 所有 `dp[i]` 之和，代码里用 `ans` 从 `dp[0] = 1` 开始逐个累加。
- 使用的数据结构：一维 `vector<int> dp`，长度 `sLen`。
- 算法流程：
  1. 初始化 `dp[0] = 1`：第一个字符本身构成 1 个新子序列，`ans = 1`。
  2. 对每个 `i`（从 1 到 `sLen-1`）：
     - 从 `j = i-1` 向左扫描，把 `dp[j]` 累加进 `dp[i]`，每加一次就取模；
     - 一旦遇到 `s[i] == s[j]`（`j` 就是最近一次出现相同字符的位置 `p`）就 `break`；
     - 如果一路扫到 `j == 0` 都没有遇到相同字符，说明 `s[i]` 之前从未出现过，此时再 `dp[i]++`，表示"空串 + s[i]"这个单字符子序列。
  3. `ans += dp[i]` 并取模；循环结束后返回 `ans`。
- 为什么这样做：把 `s[i]` 接到任意已存在的子序列（以及空串）后面，会得到一批"以 `s[i]` 结尾"的候选串。若 `s[i]` 是第一次出现，这批候选全部是新的；若最近一次相同字符出现在 `p`，则 `p` 之前就形成的子序列再接上 `s[i]`，早在位置 `p` 拼过一遍，会重复，真正的新增只来自"位置 `p` 及其后才新产生的子序列"。于是 `dp[i] = dp[p] + dp[p+1] + ... + dp[i-1]`（首次出现时还要加 1）。
- 关键状态 / 变量：`dp[i]` 是"新增量"而不是"以 i 结尾的总量"；`ans` 累计总量；内层循环的 `break` 是去重边界。
- 为什么能够得到正确答案：不同子序列按"第一次被制造出来的位置"恰好被分到唯一的 `dp[i]`，既不重叠也不遗漏。用前缀和视角看，`dp[i]` 就是 `前缀 i-1 的总增量 − 位置 p-1 之前的总增量`，多出的部分全部是与历史重复的串，截断掉即可。
- 验证：用与代码等价的 Python 逻辑对样例 `"abc"`（7）、`"aba"`（6）、`"aaa"`（3）、`"abab"`（11）等以及 800 组随机小规模输入与暴力枚举（枚举全部子序列后去重）交叉验证，结果一致。本机没有 C++ 工具链，未对 C++ 代码做编译级验证。

## 代码

```cpp
class Solution {
public:
    int distinctSubseqII(string s) {
        int mod=1e9+7;
        int ans=1;
        int sLen=s.size();
        vector<int>dp(sLen,0);
        dp[0]=1;
        for(int i=1;i<sLen;++i){
            for(int j=i-1;j>=0;--j){
                dp[i]+=dp[j];
                dp[i]%=mod;
                if(s[i]==s[j]){break;}
                if(j==0){dp[i]++;}
            }
            ans+=dp[i];
            ans%=mod;
        }
        return ans;
    }
};
```

## 代码分析

- 正确性：正确。核心是"最近相同字符位置 `p` 之后的 `dp` 才计入新增"，递推与去重逻辑成立；已用等价实现与暴力枚举交叉验证。
- 关键实现：先 `dp[i] += dp[j]` 再判断 `s[i] == s[j]` 并 `break`，顺序不能反——必须把位置 `p` 本身对应的 `dp[p]` 累加进去后再停；`j == 0` 时的 `dp[i]++` 只在字符首次出现时执行，对应只由 `s[i]` 构成的单字符子序列。
- 潜在 Bug：
  - 若 `s` 为空，`dp[0]` 会越界且 `ans` 的初值也无意义；本题约束 `1 <= s.length <= 2000`，不会触发。
  - `dp[i]++` 之后没有再次取模，最坏让 `dp[i]` 恰好等于 `10^9 + 7`（模意义下等价于 0）。由于后续每次累加都紧跟取模、且任何中间和不超过 `2 × (10^9 + 7) < INT_MAX`，不会溢出、结果仍然正确，但写成 `dp[i]++; dp[i] %= mod;` 更规范。
- 可以改进的地方：原解法思路可以进一步压缩成 O(n)。例如维护 26 个桶记录"以每个字母结尾的不同子序列数"，每次遇到 `s[i]` 时把对应桶更新为当前总数 + 1（同一字母的旧桶值被覆盖，天然完成去重），最后返回 26 个桶之和；或维护前缀和与每个字符最近出现的位置，把内层区间和变成 O(1) 查询。此处保留用户的原始实现，不做替换。

## 复杂度

- 时间复杂度：外层循环 O(n)；内层循环从 `i-1` 向左扫描，单层最坏 O(n)，因此通用上界为 O(n²)。不过 `s` 只含 26 种小写字母：把同一个字符相邻两次出现的扫描步数累加后相互抵消，总迭代数等于各字符"最后一次出现下标"之和，至多约 26(n−1)，所以本题规模下实际很小（n ≤ 2000）。
- 空间复杂度：O(n)，用于一维 `dp` 数组，其余只有常数个变量。

## 易错点

- 一定要**先累加再判断相等并 break**：顺序反过来会漏掉 `dp[p]`，其中 `p` 是最近一次相同字符的位置。
- 想清楚 `dp[i]` 是"新增的不同子序列个数"，不是"以 `s[i]` 结尾的总数"；把增量当总量会重复计数。
- 首次出现的字符要额外 +1（空串接上该字符）；若误把 +1 放在每次循环里，答案会多算。
- 单字符输入 `n = 1`：循环不执行，答案就是 1。
- 取模要边累加边做，不要攒到最后再统一取模，否则 `int` 可能溢出。
- 重复字符是本题唯一的"陷阱"来源：相同的子序列只能算一次，去重要落实到"最近一次出现位置"上。

## 总结

计数"不同子序列"的核心是去重：重复字符出现时，只有把它接到"上一次出现该字符的位置及之后才产生的子序列"上才产生新结果，接到更早的子序列上会与历史结果重复。代码中的 `break` 就是这一去重边界的直接实现；而 `dp[i]` 定义为每次新增量，答案等于所有增量的和，等价于前缀和差分 `dp[i] = 总增量[i-1] - 总增量[p-1]`（首次出现时再加 1）。

## 复盘

- 我哪里容易想错：看到"子序列计数"容易直接写"以当前位置结尾的总数 = 所有前缀 + 1"，遇到重复字符就会把同一子序列数进多个位置。
- 关键突破点：把每个不同子序列按"它第一次被制造出来的位置"归类，让每个位置的 `dp[i]` 之间互斥，问题就变成求"每次新增了多少"。
- 下次看到什么特征应该想到这个算法：给一个字符串、统计不同的非空子序列个数并取大模，优先想到序列 DP + 按最近相同字符去重；这类题通常还可以用 26 个"结尾字母桶"优化到 O(26n)。
