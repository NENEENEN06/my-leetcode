# 856. Score of Parentheses
- Difficulty: Medium
- Topics: String, Stack
- Language: C++
- 题目链接: https://leetcode.cn/problems/score-of-parentheses/

## 题目
给定一个合法括号串 `s`，按规则计算得分：`"()"` 得 1 分；`AB` 得 A+B 分（拼接相加）；`(A)` 得 2×A 分（嵌套翻倍）。

## 我的思路
不用栈，也不需要真的做嵌套拆解：**每个「紧挨着的 `()` 对」都对总分贡献 2^d，其中 d 是它外面套的层数**（即处理完这个 `)` 之后，还没闭合的左括号个数）。一趟扫描累加这些贡献即可。

- `left`：当前未闭合的左括号数（净深度），遇 `(` 加一、遇 `)` 减一。
- 判断「紧挨的 `()` 对」：`s[i]==')'` 且 `s[i-1]=='('`。
- 这一对的层数就是**减完之后的** `left`（它外面套了几层），贡献 `2^left`，累加进 `res`。
- 其它位置的 `)`（对应的是嵌套的右端）不加分，因为它们的贡献已经被内部的 `()` 对按 2 的幂次包含了。

为什么正确（归纳角度）：任何合法括号串都可以唯一分解成若干「最外层并列的部分」，而由规则 `(A) = 2A`、`AB = A + B` 可知 —— 最终得分等于所有**极小单元 `()`** 的贡献之和，每个极小单元每被一层括号包住就翻倍一次，所以它贡献 `2^d`。`d` 正是它被嵌套的层数，也就是代码里减完的 `left`。

## 代码
```cpp
class Solution {
public:
    int scoreOfParentheses(string s) {
        int res=0;
        int left=0;
        int n=s.size();
        for(int i=0;i<n;i++){
            if(s[i]=='('){
                left++;
            }
            if(s[i]==')'){
                left--;
                if(s[i-1]=='('){
                    res+=pow(2,left);
                }
            }
        }
        return res;
    }
};
```

## 代码分析
- 正确性：正确。随机对拍用**栈模拟**（遇 `(` 压 0；遇 `)` 弹栈顶 v，把 `max(2v,1)` 加到新的栈顶）和**递归下降解析**两种独立实现，合法括号串 20 万组零不一致；经典用例 `"()"`→1、`"(())"`→2、`"()()"`→2、`"(()(()))"`→6、`"((()))"`→4 全部吻合。
- 关键实现：用「`s[i-1]=='('`」识别极小单元，用「减完的 `left`」当幂次——两个小观察合起来把嵌套拆解问题压成一次线性扫描，空间 O(1)。
- 潜在 Bug：无（在题目保证输入合法、长度 ≤ 50 的前提下）。两点说明：
  1. `pow(2, left)` 返回 **double**，再隐式转回 int。本题最大深度 25、`2^24 = 16777216` 在 double 里是精确值、也没超 int，所以结果正确；但这属于「用浮点做整数幂」的坏习惯，换成 `1 << left` 更贴合语义也更快。
  2. `s[i-1]` 在 `i == 0` 时会越界读——本题因为「合法括号串的第一个字符必为 `(`」，`s[0] == ')'` 不可能出现，所以不会触发；但如果题目放宽输入（允许非法串），这里就要加 `i > 0` 保护。
- 可以改进的地方：`pow(2,left)` → `1 << left`；`left` 改名 `depth` 更达意；两个并列 `if` 可合成 `if/else if`（一个字符不可能既是 `(` 又是 `)`，当前写法没有 bug，只是多测一次）。

## 复杂度
- 时间复杂度：O(n)。一次线性扫描，每个字符常数次操作（`1 << left` 是 O(1)，`pow` 虽然常数级但常数大得多）。
- 空间复杂度：O(1)。只用一个深度计数器和累加器，栈模拟法需要 O(n) 的栈。

## 易错点
- **幂次用错时机**：必须在 `left--` **之后**取幂次。若在减之前取，每个极小单元会多乘一次 2（`"(())"` 会算成 4 而不是 2）。
- **没判断「紧挨的 `()`」就直接加分**：对每个 `)` 都加分会把嵌套结构重复计算（`"(())"` 会算成 1+2=3）。
- **`pow` 的浮点陷阱**：`pow(2, left)` 是 double 运算；本题规模下精确，但若把长度上限放大到 `2^53` 以上或把它当大数用，就会出精度问题。整数幂一律用 `1 << k`（注意 `k < 31` 才安全，再大要换 `long long`/大数）。
- **`s[i-1]` 越界**：依赖「首字符必为 `(`」这一输入保证；放宽输入时需加边界判断。
- **把得分当 long long 之外的更大数**：本题长度 ≤ 50，得分最大 2^24，`int` 足够；但若题面改成更长的串，就要换 `long long`。
- **误解 `AB` 规则**：`"()()"` 是 1+1=2，不是 2×1；只有**被括号包住**才翻倍。

## 总结
「括号串得分」的公式化结论：**得分 = Σ 每个极小单元 `()` 的 2^(被嵌套层数)**。它把「拼接相加、嵌套翻倍」的递归定义，等价转换成「统计每个极小单元被套了几层」，于是既不需要栈、也不需要递归。这与括号问题的常见套路一致：**只要能用一个深度计数器刻画前缀状态，就能把栈省掉**。

## 复盘
- 容易想错的地方：直接照着定义递归/用栈模拟（能做但要多写代码、多花 O(n) 空间）；或把每个 `)` 都当成一次加分。
- 关键突破点：认出「嵌套翻倍」的净效果就是「每个极小单元按层数乘 2 的幂」，于是只需在扫描时抓出所有紧挨的 `()` 并拿到它当时的深度。
- 下次看到什么特征应该想到这个算法：题目用递归方式定义分数（`AB=A+B`、`(A)=k·A`）且结构是括号嵌套时，先想想「能不能展开成每个最内层单元的加权和」——往往能把递归/栈压成一次线性扫描。
