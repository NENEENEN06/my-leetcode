# 1401. Circle and Rectangle Overlapping
- Difficulty: Medium
- Topics: Math, Geometry
- Language: C++
- 题目链接: https://leetcode.cn/problems/circle-and-rectangle-overlapping/

## 题目
给定圆心 `(xCenter, yCenter)`、半径 `radius`，以及一个边与坐标轴平行、左下角 `(x1, y1)`、右上角 `(x2, y2)` 的矩形，判断圆与矩形是否相交（相切也算）。

## 我的思路
圆与轴对齐矩形是否相交，等价于「矩形上离圆心最近的那个点到圆心的距离 ≤ 半径」。而矩形上离圆心最近的点，就是把圆心的 x、y 分别**夹**（clamp）进矩形的两个坐标区间：

- `x`：圆心横坐标落在 `[x1, x2]` 内就取 `xCenter` 本身，偏左取 `x1`，偏右取 `x2`；`y` 同理取 `y1 / yCenter / y2`。
- 得到最近点 `(x, y)` 后，比较平方距离：`(x-xCenter)² + (y-yCenter)² ≤ radius²`。
- 用平方比较省掉开方，也避免浮点误差；相切（等号）按题目要求算相交。

为什么这是最近点：矩形的可行 x 区间是 `[x1, x2]`，对固定的 y，函数 `(x - xCenter)²` 在 `xCenter` 处最小、在区间外随距离单调增，所以夹取就是取到该方向上的最小值；x、y 两个方向互相独立，平方距离是可加的，两者同时取最小即整体最小。

关键变量就是 `x`、`y`（最近点坐标），没有其他状态。

## 代码
```cpp
class Solution {
public:
    bool checkOverlap(int radius, int xCenter, int yCenter, int x1, int y1, int x2, int y2) {
        int x,y;
        if(xCenter>x2){x=x2;}
        else if(xCenter<x1){x=x1;}
        else{x=xCenter;}
        if(yCenter>y2){y=y2;}
        else if(yCenter<y1){y=y1;}
        else{y=yCenter;}
        return (x-xCenter)*(x-xCenter)+(y-yCenter)*(y-yCenter)<=radius*radius;
    }
};
```

## 代码分析
- 正确性：正确。圆心落在矩形内部时 `x=xCenter, y=yCenter`，距离为 0，必然 ≤ r²（`radius ≥ 1`），符合直觉；圆心在外部时夹取给出真实最近点。随机对拍本机的独立实现（把「点到矩形距离」换成「到四条边的线段距离取最小」这一等价但不同的算式）结论一致。
- 关键实现：两个方向分别 clamp，最后统一用平方距离比较；全程整数运算，无浮点。
- 潜在 Bug：无。参数范围 `-10^4 ≤ 坐标 ≤ 10^4`、`radius ≤ 10^4`，坐标差最大 2×10^4，平方 4×10^8，两项相加 8×10^8，`int`（2.1×10^9）装得下，不会溢出。
- 可以改进的地方：仅可读性 —— 两层 `if/else if/else` 可用 `std::clamp(xCenter, x1, x2)` / `std::clamp(yCenter, y1, y2)` 一行带过（C++17 起可用）；布尔表达式可直接 `return`，现在也是直接 return，没问题。

## 复杂度
- 时间复杂度：O(1)。两次比较 + 一次平方距离比较，与坐标大小无关。
- 空间复杂度：O(1)。只有两个 int 中间变量。

## 易错点
- **用圆心到矩形中心的距离判断**：只有圆形矩形（正方形内切圆）才巧合成立，一般情况会误判。
- **相切算不算相交**：题目要求算，所以用 `≤` 而不是 `<`；写成 `<` 会漏掉 `radius²` 正好等于平方距离的用例。
- **溢出**：若把坐标范围放大（比如 10⁵），平方项就会超 `int`，此时必须换 `long long`；本题范围内安全，但要知道这个边界在哪。
- **只夹一个方向**：x、y 必须各自独立夹取；漏掉一个方向相当于把最近点约束在一条线上。
- **% / 浮点开方**：`sqrt` 比较会引入精度问题，等价的平方比较更稳。

## 总结
「圆与轴对齐矩形相交」的标准套路是**夹取最近点 + 平方距离比较**：把圆心分别 clamp 到矩形的 x、y 区间，得到矩形上离圆心最近的点，再比距离与半径。这一招可以推广到圆与线段、圆与矩形的近似判定，也是碰撞检测里最常用的几何原语之一。

## 复盘
- 容易想错的地方：第一反应是判断圆心在不在矩形内、或者拿圆心到中心的距离比，这两种都不对；关键在于「最近点」而不是「中心」。
- 关键突破点：识别出 x、y 两个方向的可分离性——平方距离对两个方向可加，所以各自取最小即可，不需要真的做二维优化。
- 下次看到什么特征应该想到这个算法：出现「圆/球 + 轴对齐盒子」的相交判断，先想夹取最近点；只要是轴对齐的，答案都是几行代码。
